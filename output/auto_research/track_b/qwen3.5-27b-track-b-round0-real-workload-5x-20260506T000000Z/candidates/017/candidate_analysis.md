- speed_thesis: Use vLLM ngram speculative decoding with a very conservative proposal shape, `num_speculative_tokens=1` and a short prompt lookup window, to capture repeated prompt-local continuations in the warm workload without increasing launch capacity or changing model weights. A one-token draft keeps verification overhead low and may improve accepted-token-per-step behavior where prompt reuse is present.
- expected_affected_counter: Warm decode tokens/sec should move if the workload has enough local ngram overlap for accepted proposals; prefill and cold-start behavior are not the target because the first cold completion is discarded.
- quality_risk: Low. Ngram speculative decoding proposes candidate tokens from prompt text and vLLM verifies them against the target model before acceptance, so target model weights and sampling semantics remain preserved. The main risk is runtime instability or overhead if proposal acceptance is too sparse.
- why_not_prior_failure: This is not a CUTLASS tile, schedule, stage, or caller mutation, and it does not repeat the flat request-shaping or launch-capacity surfaces. Candidate 013 used a wider ngram shape with four speculative tokens and lookup range 2-32 that failed measurement; this candidate narrows to one speculative token with lookup range 1-8 to reduce scheduler and verification pressure while still testing the same serving lever.
