- speed_thesis: Use vLLM ngram speculative decoding with a slightly longer 3-token draft and a wider prompt lookup window (`prompt_lookup_max=16`) to exploit repeated prompt and response fragments in the warm real-workload window. Candidates 017 and 018 showed the ngram surface can run stably and slightly led the audit despite missing the acceptance threshold; this shape tests whether more lookup context can raise accepted draft tokens without the heavier failed 4-token/32-window configuration.
- expected_affected_counter: Warm decode tok/s should be the primary affected counter, with possible secondary changes in speculative draft acceptance, effective decode steps per output token, and scheduler overhead. Prefill and cold-start behavior are not the target because the first cold completion is discarded.
- quality_risk: Low semantic risk because ngram speculative decoding should preserve target-model verification and sampling behavior; rejected draft tokens fall back to normal target decoding. Runtime risk is moderate because candidate 013 had a throughput measurement failure on a more aggressive ngram shape, so this keeps `prompt_lookup_min=1` and uses a smaller max window than 32.
- why_not_prior_failure: This does not retry exhausted CUTLASS tile, schedule, stage, or caller mutations, and it does not rely on flat launch-capacity-only vLLM knobs. It is distinct from prior measured serving surfaces: unlike 017 and 018 it uses a 3-token speculative draft and `prompt_lookup_max=16`; unlike failed 013 it avoids the 4-token draft with `prompt_lookup_min=2` and `prompt_lookup_max=32`.
