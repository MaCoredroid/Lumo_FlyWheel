## PART 1 — GATE-TRANSFER MATRIX (every ledger item classified)

Classification key:
- **TRANSFERS-AS-IS** — exercised code path is provably disjoint from the replay diff surface; evidence + instrument carry verbatim.
- **TRANSFERS-CONDITIONAL-ON-BYTE-A/B** — the property/evidence carries IF AND ONLY IF the one-time byte A/B (Gate A below) passes; otherwise the trajectory differs and the recorded numbers are for a different run.
- **MUST-RERUN-CHEAP** — harness transfers but the verdict must be re-earned on the replay route (boot counts given).
- **REPLACED/NEW** — old gate's semantics no longer apply; a replay-route counterpart must be built.

## PART 2 — DRIFT-RISK TAXONOMY (ranked, each mapped to its catching gate)

P = `scripts/fr10_phase4_patch_vllm_tree_gdn.py`, K = `src/lumo_flywheel_serving/fr10_gdn_tree_kernel.py`.

**R1 — Commit-time index generation: h0 column from the WRONG lens generation + zero-accept/first-step conflation. [HIGH × WHOLE-SEQUENCE]**
The scan reads h0 at row `spec_state_indices[b, clamp(prev_len-1,0)]` (K:333-342, args P:2474-2480) using the PREVIOUS event's lens; at commit the committer OVERWRITES the same persistent buffers with NEW lens (P:3625-3638) before any publish-site replay runs → replay deriving its h0 column from the live buffer reads the NEW lens → wrong h0 row → gate-4-shaped accept collapse (2.024→1.521). Zero-accept: paths EXCLUDE the root (+1-shifted node ids P:3599-3606), lens CAN be 0; today column 0 survives only because node-keyed publish leaves node-0 (root) state there while remap masks out (K:150-151). Replay must write column 0 = root state on len=0 TREE events; step t+1 stored at column t (column 0 = first accepted draft node, NOT root); and must NOT write for requests with no tree forward this step (REQKEY zeros P:5306-5308, resume-after-preempt). Bonus token has no state this event.
*Caught by:* Gate B (live ordering probe) + Gate A run as two-event sequence at all lens incl. len=0/len=max/first-spec-step + Gate C; final catcher Gate F. *Mitigation:* prev-lens snapshot buffer captured BEFORE P:3625's copy_ (or launch replay before the overwrite with new path/lens as separate tensors); per-step "ran-tree-forward" flag gating row-0 writes.

**R2 — Composition with the remap + LINEAR-vs-NODE column conventions. [HIGH × WHOLE-STATE]**
Replay writes LINEAR ssm columns at commit. If the ssm remap half (K:261-269) still runs next forward it re-permutes already-linear rows using NODE-id paths = total corruption. If the conv half (K:270-278) is deleted along with it, the conv prior-window read (P:804-821) reads NODE-keyed conv rows with a LINEAR column index = re-creates the FR13 conv-prior-window bug. The two banks intentionally live in DIFFERENT conventions during the inter-step window (ssm linear after replay; conv node-keyed until next forward's conv remap) — "unifying" them drifts. Conv write-back stays node-keyed + dtype-cast (P:1293-1295, :1321-1327) — do not touch.
*Caught by:* Gate E (durable-state diff=0 column-by-column, every len) + item-1 ladder (conv1d_out staircase stays 0) + re-pointed `fr10_serving_wiring_gate.py`. *Mitigation:* ONE atomic commit that (a) gates the kernel store off, (b) installs replay, (c) disables ONLY the ssm remap half, (d) asserts mutual exclusion of FR13_REPLAY_ROUTE with the legacy publish path (fail-loud).

**R3 — CUDA-graph stale captured pointers. [MED-HIGH × SILENT-AT-FINAL-GATE]**
Proven in-repo precedent (gate-4 root cause #2): per-step allocations pinned across the forward→sampler boundary alias differently per batch-size graph under FULL capture → silently stale buffers, ONLY in the captured regime (eager dev runs all pass). If the activation ring is allocated inside the forward, graph replays write the capture-time pointer while the eager commit-side replay reads a different allocation. Replay launch sits OUTSIDE the captured region (Option 1, commit-time); its inputs must be persistent device buffers (paths/lens P:188-201, ring, live spec_state_indices) — never CPU snapshots or python-held per-step refs.
*Caught by:* item-11 NEW capture gates — durable-state diff=0 UNDER B=4 FULL capture with varying batch composition (NOT eager) + ring step-counter liveness canary; final catcher Gate F. *Mitigation:* ONE persistent preallocated per-layer ring at metadata-builder init (P:184-201 pattern), sized max-B × n_pad, slot-indexed; no dicts, no per-step allocs.

**R4 — Codegen: "shared @triton.jit body" IS NOT "shared SASS". [MED × EVERY-TOKEN, deterministic once gated]**
Every jit helper is INLINED; each (kernel, constexpr-set, dtypes, num_warps) tuple compiles independently (separate PTX→ptxas→SASS). The scan is specialized on (N_ACTUAL,N_PAD) with 128KB h_cache register pressure (K:352); the replay sibling has MAX_PATH_LEN bounds and one tile — ptxas may legally differ on FMA contraction (`state_i += b_v[:,None]*b_k[None,:]` K:416) and reduce lowering (K:414, l2norm K:408-410). In-repo proof this class flips bits: A1 (1-D vs 2-D reduce = 1.19e-7, `FR13_REPLAY_CHASEDOWN_BANK.md`; BV=1 collapse `FR13_BV_SPILL_VERDICT.md`), A10 (static_range batch-dependence).
*Caught by:* Gate A with the FULL coverage matrix (every served family × every len × both real launch contexts × all layers × −0.0 and dst==h0 cases, durable bank bytes, bit-equality). *Mitigation:* identical tile shapes, identical op factoring of K:408-417 into one shared inlined body, no @triton.autotune (L0c lesson), pin cubin/SASS hashes, re-arm A/B per toolchain change. Source-sharing is a likelihood reducer only; the A/B is the load-bearing proof.

**R5 — Activation-capture seam: aliasing, mutation window, dtype. [MED × ALL-STATES]**
The scan consumes `.contiguous()` slices (P:2464-2471) which ALIAS live storage when already contiguous — stash-and-copy-at-commit reads whatever the storages hold THEN (layer temporaries recycle). The ring store must byte-copy at the launch site on the SAME stream (device equivalent of the diagnostic `.detach().cpu().clone()` at P:2703-2728). Dtype: bf16→fp32 widening is EXACT and path-identical (kernel widens at load, K:367/:372/:377/:394/:399); drift enters only if the ring changes dtype, round-trips through narrower types, or stores POST-l2norm k (stored k MUST be pre-norm; l2norm is in-kernel, P:2488/K:408-410). Under RAW_GATING store raw_a/raw_b only (g/beta loads are dead, K:389-406); recomputed softplus/sigmoid/exp hit the same libdevice → same bits.
*Caught by:* debug capture-integrity canary (checksum ring row at scan time vs commit time) + dtype/stride asserts + Gate A (transitively proves bytes survived). *Mitigation:* copy-at-launch-site; ring layout `[layer][slot][node]` mirroring start:end row order so `ring[b, accepted_path[t]]` is the trivially-correct mapping.

**R6 — H0 row isolation between scan-read and replay-read. [LOW × CATASTROPHIC]**
Writers in the intra-step window, with verdicts: (a) the all-rows publish P:2751-2755 — deleted by the route, ASSERT actually gone (replay-after-publish reads wrong-generation h0); (b) chunked-prefill non-spec rows P:3050-3052 — disjoint; ASSERT pairwise disjointness of all batch rows' spec_state_indices (block-pool aliasing = the only break, catastrophic + silent); (c) FR12 native-spine splice P:2536-2543 — env-gated oracle; HARD-RAISE if FR12_NATIVE_SPINE_ORACLE=1 with replay on; (d) conv writes — different tensor; (e) the replay itself: dst column t can equal the h0 column — safe ONLY because each program reads its full h0 tile into registers BEFORE any store (per-depth separate launches or multi-pass would break this); (f) other layers — disjoint tensors; (g) vLLM native mamba_utils spec-state copy (the L224-254 contract) — VERIFY the native ssm copy is neutralized under tree mode (live-container source read; currently UNCERTAIN whether only the conv side is overridden). Option 2 (next-step prologue replay) widens the window across the scheduler — prefer Option 1 for bring-up.
*Caught by:* debug h0-row byte checksum (the `_fr10_event_h0` clone machinery P:2448-2463, gated) re-verified at replay launch + row-disjointness assert + Gate A two-event sequence. *Mitigation:* Option 1; in-kernel read-tile-before-store discipline; the (a)/(c)/(g) asserts.

**R7 — ±0.0 per-edge normalization + root-unnormalized. [CERTAIN byte-mismatch if unhandled × LOW value impact, but breaks the gate methodology]**
`h_j = tl.sum(tl.where(offs_n==j, h_cache, 0.0))` (K:356-360) canonicalizes −0.0→+0.0 exactly once per edge; the root (i=0, empty ancestor loop, K:354) passes h0 bytes UN-normalized. A naive register-walk replay never canonicalizes → stored bytes differ wherever an element is −0.0. Value-identical downstream (state feeds only mul/add/sum K:413-417) — but the verdict mechanism is BYTE equality, and granting tolerance re-opens the FR11 tolerance-mindset failure. Fix in-kernel: `state += 0.0` once per edge for t≥1, never on root h0, never after the final store (stored node states are NOT post-normalized). Masked replay steps (t ≥ accepted_len) must be bit-transparent (masked loads, `other=0.0`).
*Caught by:* Gate A's mandated synthetic −0.0-in-parent and −0.0-in-h0 cases. *Mitigation:* the per-edge `+0.0` rule above, encoded in the shared body.

**R8 — REQKEY composition: ring keying vs request re-keying, dict cleanup, double-zeroing. [MED × PER-REQUEST at B=4 churn]**
The REQKEY pre-forward rewrite (P:5235-5350) re-installs slot occupants' path/lens (zeros for first spec step P:5306-5308) and deletes dead entries (P:5281-5283). The ring is a NEW slot-keyed stateful artifact with exactly the staleness REQKEY was built to kill: a slot's new occupant replaying over the previous occupant's activations. Option 1 keeps the slot mapping intra-step stable (committer's `_LUMO_FA_SAMPLER_ROW_REQ_IDS` P:3658-3669 is the same step's) → exposure reduces to R1's first-step/zero-len conflation; Option 2 requires request-keyed or REQKEY-invalidated ring. Ordering chain (document the replay's position explicitly): committer fills device buffers (P:3625-3638) → REQKEY dict (P:3677-3681) → next-step pre-forward rewrite → remap (P:759).
