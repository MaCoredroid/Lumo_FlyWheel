Lossless-within-floor GDN Tree-Scan

Served-Realization Tree Verification for Recurrent Hybrid Models

A native-compatible tree verifier for token trees on a 75% recurrent hybrid model. The contribution is served-realization equivalence for Qwen GDN inside vLLM: FA2 ancestry, path-local recurrent state, accepted-chain replay, and state publication all tied back to native decode.

TL;DR: a draft tree is a menu of next-token guesses. On this Qwen hybrid, the verifier is distribution-preserving within the native recurrent-oracle floor only if two path-local facts hold at once: attention rows see prefix plus ancestors, and each GDN row carries the recurrent state native decode would have produced on that branch. We use the native MTP head here, but the verifier boundary can serve another drafter if it supplies the same tree contract.

Abstract

We present a native-compatible tree verifier for speculative decoding on Qwen 3.6-27B-FP8, a hybrid model whose 64 layers include 48 Gated-DeltaNet recurrent layers and 16 softmax-attention layers. The core problem is not tree speculative decoding in general; prior work already establishes that. The core problem is served-realization equivalence for this recurrent hybrid inside vLLM, including fp8/bf16 seams, the FA2 attention realization, GDN state publication, and accepted-chain replay.

Formally, the result is distribution-preserving within the native recurrent-oracle floor. In the rest of the page, lossless is shorthand for that scoped claim, not a universal bit-exact theorem. The implementation combines a forked FlashAttention-2 tree-bias path, a Triton GDN tree scan/replay kernel, vLLM tree-shape packing, device-side multidraft commit, and deployment-mode measurement gates. In the clean B=1/temp-0.6 deployment run merged to main on June 17, 2026, both depth-5 tree shapes beat native E5 (native 5-step MTP spine) and both close within the native floor.

Formal lossless definition: in this paper, lossless means distribution-preserving within the native recurrent-oracle numerical floor, not bit-identical logits at every intermediate tensor.

Verifier Contract

Theorem style: this is the formal contract the implementation is trying to realize. The proof is structural; the numerical and served-path claims are empirical gates.

The verifier receives a candidate tree from any drafter, not necessarily the native MTP head. The contract below is what makes the target path distribution-preserving within the native floor after verification and publication.

Accepted-state theorem, engineering form: assume the candidate tree only contains candidate token ids and parent links; attention rows can see only prefix plus ancestors; every GDN row is computed from its parent row's recurrent state; the committer applies the same SpecInfer residual rule; and durable state is replayed/published only for the accepted chain. Then the next served decode event starts from the same observable token prefix and recurrent state that native sequential decode would have reached on the accepted tokens, up to the native recurrent-oracle numerical floor.

Prior Work

Speculative decoding: a cheaper draft path guesses future tokens, then the full model verifies them. If the verifier rejects a guess, the algorithm falls back without changing the target distribution.

Tree decoding: instead of one draft chain, the draft proposes several possible branches in one verification pass.

Tree speculative decoding is well studied for Transformer-style attention stacks. SpecInfer introduced tree-based speculative inference and parallel verification while preserving model quality. Sequoia made the tree shape hardware-aware. EAGLE-2 uses context-aware dynamic draft trees while keeping the output distribution unchanged. OPT-Tree frames the tree shape as an acceptance-versus-overhead optimization problem.

The closest prior work for this project is STree, which studies speculative tree decoding for state-space and hybrid models by exploiting accumulated state-transition structure. The key difference is the realization contract. For this vLLM/Qwen target, it is not enough to say that the algebraic state for a tree exists. The served verifier must reproduce native-path semantics through fp8/bf16 kernels, branch co-residency, durable state writeback, and rejection sampling.

Recent hybrid/SSM serving work sharpens the same boundary. SpecMamba names hidden-state backtracking, tree-verification incompatibility, and draft/target workload mismatch as the core obstacles for Mamba speculative decoding, then solves them in an FPGA setting with FIFO-based tree verification and hardware dataflow. Component-Aware Self-Speculative Decoding in Hybrid Language Models evaluates Falcon-H1 and Qwen3.5, showing that hybrid integration pattern determines whether an internal SSM/linear-attention drafter is viable; its implementation section explicitly leaves fused CUDA kernels, batched verification, and cache sharing as needed systems work. SGLang's hybrid-model production writeup frames the operational issue similarly: SSM state updates are in-place, rejected tokens cannot be rolled back like KV cache, and EAGLE-tree attention masks do not by themselves maintain SSM state.

SGLang is therefore the most important adjacent served comparison, not a side note, but it is not an apple-to-apple kernel baseline for this page. Its hybrid writeup separates KV cache from request-level Mamba state, adds MambaRadixCache for prefix caching, and handles speculative verification with independent Mamba cache slots for draft tokens plus parent-index tracing. That is primarily a serving-cache and scheduler-layer attack on the problem. This page's shipped contribution is lower in the stack: branch-local fused GDN tree scan/replay, a forked FA2 tree-bias verifier path, vLLM state publication, and an explicit lossless-within-floor measurement contract. A vLLM-side radix/prefix state-cache design would be complementary future work, not the current head-to-head claim.

SGLang's Qwen3.6 docs now list Gated Delta Networks variants with MTP weights and an EAGLE-style speculative command. That matters for positioning: "serving a GDN hybrid with speculation" is not the novelty by itself. The narrower claim here is served-realization equivalence for the vLLM/FA2/GDN verifier path and the measurement discipline used to prove it within native floor.

A live correctness issue makes the comparison sharper. SGLang issue #25587, opened May 18, 2026, reports Hybrid-GDN MTP speculative decoding on Ascend NPU diverging from non-speculative decoding at temperature=0.0. The reported root cause is accepted-state restoration after partial acceptance: verify consumes all N draft tokens, but only k <= N are accepted, so conv state must be restored to the state after the accepted prefix, not after the rejected suffix. This is the same invariant this page calls accepted-chain replay: rejected branch state must not become durable. We cite it as evidence that the served correctness boundary is backend-dependent and still active, not as evidence that SGLang's NVIDIA path is broken.

Why This Matters

Drafter: the cheap source of candidate tokens. In this artifact it is Qwen's native MTP head.

Verifier: the target-model path that decides which candidates can be published without changing the model distribution.

The durable value is not a single caterpillar shape. The durable value is a verifier that understands both sides of this hybrid model: softmax attention and Gated-DeltaNet recurrence. Once that verifier contract exists, the drafter can change. The current paper uses Qwen's native MTP head because it is available inside vLLM, but the same verifier boundary can accept suffix decoding, an MTP-plus-suffix hybrid, n-gram candidates, or a learned external drafter if it emits the tree descriptor and candidate ids.

The second value is methodological. This work is a compact museum of how losslessness and speed were chased without letting one fake the other: scan A/Bs, replay byte gates, recurrent-oracle p-rescore, ON/OFF instrumentation separation, deployment-regime speed, shape sweeps, and failure records for approaches that were mathematically tempting but not shippable.

How We Arrived at This Design

Native MTP spine: Qwen's built-in speculative path verifies one linear chain of future tokens.

Our tree verifier: keeps that linear spine, then adds branches only if attention, GDN state, committer, and measurement all remain tied to native decode.

The final design is easiest to understand as a sequence of constraints. Native MTP already gives a strong depth-5 spine. The tree should therefore be a strict opportunity set around that spine, not a different model, a reward hack, or a looser acceptance rule. That premise forced the verifier to prove two things for every candidate node: the attention row is ancestor-only, and the GDN state is the same state native decode would have produced on that branch.

That is why the work is not just "make the attention mask wider." The intended WY-style tree algebra and STree-style state sharing were valuable references, but this deployment needed realization-level equivalence inside vLLM: fp8/bf16 kernels, FA2 attention, GDN recurrent state, sampled committer behavior, accepted-path replay, and durable state publication. Every time a shortcut passed one local test but failed a served-path gate, it became part of the design trail.

Why the near-miss designs were not enough

The three tempting shortcuts failed for different reasons. STree answered the high-level question, WY answered a speed-shaped math question, and Triton tree attention answered the mask question. None of those alone answered the actual serving question: will the token that leaves vLLM be the token the native recurrent target would have emitted under the same sampled setting?

STree

State exists is not the same as state matches

STree is the closest prior-work lens because it treats tree decoding for stateful models. The missing piece for this system is realization. The literature survey notes that STree assumes the SSM tree forward equals the SSM sequential forward; our serving path had to prove that equality under vLLM, fp8/bf16 kernels, branch co-residency, and durable writeback. The practical warning showed up immediately: native vLLM tree attention was wired, but GDN recurrent state was still linear. On real Qwen tensors, non-linear branch nodes differed by 0.5618 until the FR10 GDN tree kernel was inserted. The custom kernel then matched the native production decode/update primitive at 7.45e-09 output max-abs and 7.63e-06 state max-abs.

WY

Equivalent algebra can still choose a different token

WY-style whole-tree algebra was tempting because the tree scan carries expensive state. It promised a cleaner one-pass formulation and a route around h_cache pressure. The blocker was the oracle. Native verify for this target is a sequential rank-1 recurrence. Chunked WY is a prefill formulation, and a different summation tree is enough to change low-bit bf16/fp32 boundaries. For lossless speculative decoding, those low bits matter only when they move argmax or sampling residual decisions, but that is exactly where this project spent its time. So WY stayed useful as an fp32 oracle and last-resort speed idea; the shipped contract became sequential branch-local scan plus accepted-path replay.

TREE_ATTN

A correct mask on the wrong kernel is still the wrong verifier

Triton unified_attention(..., qq_bias=...) could express tree ancestry, but native E5 used CUTLASS FlashAttention-2. The attention localization work found the mask/wiring could be right while the core attention op still differed: a post-fix attn_out_raw residual around 0.00195 per full-attention layer compounded across the 16 attention layers. Stock FA2 was not a drop-in answer either, because it had no tree-mask input; the plain flash path produced the wrong branch computation. The fork adds a real tree_bias input inside FA2 after QK and before softmax, preserving native FA2's MMA/reduction order while adding the ancestry constraint. Latest code verification says the deployed decode path uses that fork; unified_attention is only the fallback.

Algorithm 1: Tree Verification on a GDN Hybrid

Algorithm box: this is the whole served path in paper form. The kernel section then zooms into the GDN scan step.

Inputs: prefix state, candidate tree T, candidate token ids, RNG state
1. Pack T into parent indices, visible/strict masks, path rows, and candidate ids.
2. Run attention layers with FA2 tree bias: each row sees prefix + ancestors only.
3. Run each GDN layer with branch-local scan: H_i = GDN_step(H_parent(i), x_i).
4. Compute verifier probabilities q_i for candidate rows.
5. Device multidraft commit applies the SpecInfer residual rule along T.
6. Replay the accepted path in native order through GDN/conv state.
7. Publish only the accepted-prefix tokens and durable state; discard rejected branch state.

The proof obligation is attached to the outputs of steps 2, 3, and 6. Step 2 must preserve attention ancestry, step 3 must preserve branch-local recurrent state, and step 6 must ensure the next decode event starts from the accepted native-compatible state rather than from a rejected tree row.

Kernel and Math

GDN: Gated-DeltaNet is a recurrent layer. It carries a state tensor forward through the sequence.

Native path: the exact token order ordinary decode would have seen. A tree node is valid only if its recurrent state equals the native decode state for that node's branch path.

Qwen 3.6-27B is not an attention-only stack. Its recurrent layers mean that a tree verifier must compute one state per branch path. Sharing a single recurrent accumulator across flattened tree rows is wrong, because sibling rows would inherit state from branches that native decode would never have visited.

The kernel invariant is simple enough to state and hard enough to implement: for every node i, the state S_i used by the verifier must equal the native GDN recurrence evaluated over the tokens on path(root -> i).

GDN recurrence, one value tile
S'_t = exp(g_t) * S_{t-1}
delta_t = beta_t * (v_t - S'_t k_t)
S_t = S'_t + delta_t k_t^T
o_t = S_t q_t
Tree invariant: S(node i) == native_scan(tokens on root-to-i path)

Native decode

There is one chain: S0 -> F(x1) -> S1 -> F(x2) -> S2. The next token always inherits the immediately previous accepted state.

Wrong tree shortcut

A flat packed tree can run rows in parallel, but a shared accumulator makes sibling rows inherit impossible history.

Our tree scan

Each node selects its parent state from h_cache, applies the same rank-1 GDN step, and only the accepted path is replayed into durable state.

Kernel source quote: shared rank-1 GDN update body The code receipt is preserved, but not forced into the first-read path.
Source exhibit fr10_gdn_tree_kernel.py 
# shared by both tree scan and accepted-path replay
state_i *= tl.exp(b_g)
b_v -= tl.sum(state_i * b_k[None, :], axis=1)
b_v *= b_beta
state_i += b_v[:, None] * b_k[None, :]
out_i = tl.sum(state_i * b_q[None, :], axis=1)

The design choice is not a new recurrence. It is the same rank-1 update body, reused in scan and replay, with native-alignment seams gated explicitly.

Why BV and h_cache limit the kernel

BV is the value-channel tile width, called BLOCK_V in the Triton kernel. One program holds a GDN state tile with shape [BV, DIM_K]. A tree scan needs a post-state for every padded node because each child must select its own parent state. That is the h_cache: [N_PAD, BV, DIM_K] in fp32.

This is why native-match geometry does not scale directly. Native decode uses BV32 / num_warps=1 / num_stages=3. A full tree with N_PAD=16 at that geometry would demand about 256KB of fp32 h_cache in one warp, roughly 2048 fp32 registers per lane, which spills. The deployed tree scan uses BV16 / warps=8 / pad16 to fit. Native-alignment experiments use recompute/replay with one [BV, DIM_K] tile instead of caching every node.

The native-alignment seams that mattered were concrete: beta's bf16 round-trip, q/k l2-normalization by division rather than rsqrt, and the carried-state bf16 boundary after the output is computed. Those details sound small, but a tree verifier lives on margins. A one-ULP branch-local difference can become a different accepted prefix after deep recurrent and attention layers amplify it.

Fresh-reader translation

BV is how wide a slice of model memory the kernel handles at once.

h_cache is a table of branch memories. More nodes make the table bigger. If the table is too big, the GPU spills registers into slower memory, and the "correct" kernel stops being fast.

How the Kernel Connects to Attention and vLLM

FA2: FlashAttention-2. The attention layers need a tree-aware bias so each row sees exactly the ancestors it should see.

vLLM wiring: the page-level result depends on scheduler metadata, slot mapping, draft packing, sampling, and state publication matching the same tree.

The GDN scan is only one piece. The shipped tree path has to align five surfaces: the candidate tree descriptor, the forked attention kernel, the recurrent scan/replay kernel, the multidraft committer, and the durable state writeback. Most of the engineering effort was chasing cases where one of those surfaces agreed with the shape but disagreed with the path semantics.

Today the candidate tree comes from Qwen's native MTP head: root and spine tokens from the same logits tensor, with runner-up leaves as top-k reads. The verifier should not care whether tomorrow's candidates come from suffix decoding, MTP plus suffix, or another drafter. It should care that the tree has stable parent indices, visible/strict ancestry masks, candidate ids, and accepted-path rows that can be replayed into native state.

The attention side needed its own fork. Default tree attention could add a query-query bias through a generic Triton path, but that path was not the same realization as native FlashAttention-2. The fork instead keeps native FA2 prefill, then routes decode through the FA2 varlen kernel with an explicit tree bias. That gives the tree verifier ancestor visibility without changing the whole attention implementation underneath it.

Lossless Evidence and Closure Gates

Lossless shorthand: in this paper it means distribution-preserving within the native recurrent-oracle floor, not bit-exact equality to every native kernel intermediate.

BV A/B: a scan-only check showing whether different value-tile settings change the branch decision in a controlled regime.

The lossless chase found both numerical and wiring failure modes. A key lesson was that scan-only bit-exactness is not enough, and literal zero max-abs is not the right universal bar. BV A/B showed the scan op itself can be native-stable in a shallow single-forward regime, but live decode also feeds recurrent state through co-resident accepted chains, committer publication, conv prior windows, and deep attention layers.

The exact depth-5 B=1 p-rescore is now closed. Against each arm's own no-spec recurrent oracle, native E5 has 630 clear-margin flips over 4,883 positions, 12.90%; cat9 (9-node caterpillar tree) has 645 over 4,858, 13.28%; cat6root (6-node root-branch tree) has about 636 over about 4,860, 13.09%. Both tree arms are within the native E5 floor by less than one position-level standard error. That SE is optimistic because positions inside the same SWE/Codex turn are correlated. The paper therefore treats the result as clean B=1 closure for the current sample, while request-level bootstrap, more seeds, and B=4 remain follow-up gates.

Failure Library: What Did Not Work

Failure library: not a graveyard. It is the receipt trail for why the final kernel and measurement contract look the way they do.

Most failures were useful because they separated three questions: is the verifier lossless, is the kernel fast, and is the measurement regime honest?

The path to the final verifier was not linear. The important negative results are part of the paper because they prevent the same mistakes from being rediscovered: attention-only fixes, native-looking kernels that spill, lossless gates that measure the wrong frame, and speed screens polluted by concurrency or instrumentation.

Settled

Some routes were real design dead ends

Attention-only trees, shared recurrent accumulators, and native-match full-tree cache geometry each failed for structural reasons that later evidence did not overturn.

Superseded

Some conclusions were replaced by cleaner gates

Literal-zero lossless, +4% as throughput, and propose-tree Stage D attribution were useful intermediate frames, but later B=1 and phase-local evidence rewrote them.

Contaminated

Some evidence had to be quarantined

B=4 branch-yield reads, suffix/MTP shortcut accounting, and v1 hidden-state substitution each had later proof that the original measurement could not support its conclusion.

Full failure library with later-status audit Every rejected route is preserved, but contaminated and superseded conclusions are explicitly marked.

Status key: settled means later evidence still supports the negative result; superseded means the raw observation may be real but the old framing is replaced; contaminated means the old measurement or instrument cannot support the conclusion; open means useful but not closed under the final gates.

This is intentionally verbose. The point is to show how the design converged: not by declaring every old route wrong, but by separating structural dead ends from bad evidence, stale framing, and still-open follow-up work.

Attention-mask-only tree

settled

Why it looked plausible: most Transformer tree-verifier discussions reduce the problem to ancestry masking: row i can see the prompt and its ancestors, and cannot see siblings.

  • Evidence: the FR10 real-tensor de-risk showed native vLLM tree state contamination in the GDN path, while the custom GDN tree kernel matched the native isolated decode/update path at tiny numerical deltas.
  • Later check: nothing in the B=1 closure overturned this. The final verifier still needs both FA2 tree bias and branch-local GDN state.

Conclusion: tree attention is necessary but not sufficient. The paper's real invariant is attention ancestry plus path-local recurrent state plus accepted-chain replay. Receipt.

Shared packed recurrent accumulator

settled

Why it looked plausible: flattening all tree nodes into one packed forward is the simplest way to keep the GPU path dense and avoid per-branch Python control flow.

  • Evidence: sibling rows can inherit recurrent state from branches that native sequential decode never visited. The bug is not visibility through attention; it is state lineage through GDN recurrence.
  • Later check: the clean B=1 result closed only after branch-local scan and accepted-chain replay were part of the served contract.

Conclusion: a single shared accumulator is invalid for co-resident branches. The surviving mechanism is the branch-local h_cache scan, followed by replay of the accepted chain before publishing state.

STree-style state sharing as a direct transplant

settled

Why it looked plausible: STree is the closest prior-work framing for tree decoding in SSM/hybrid models, so it was the right place to borrow language about stateful tree verification.

  • Evidence: the literature mapping found that prior lossless arguments assume the tree forward realizes the same target distribution as sequential decode.
  • Gap: our problem is lower level: branch co-residency, bf16/fp8 codegen, FA2 versus Triton attention realization, and vLLM state publication can break served equivalence even when the algebraic state exists.

Conclusion: STree transfers as problem framing, not as a drop-in implementation proof. This paper's differentiator is served-realization equivalence inside vLLM. Receipt.

Triton TREE_ATTN as the proof attention path

superseded

Why it looked plausible: vLLM already had a tree-attention route through unified_attention with a bias mask, so it seemed natural to use that as the verifier's attention implementation.

  • Evidence then: the Triton path provided the right ancestry-mask semantics, but not the native FA2 decode realization.
  • Later correction: the drift reanalysis corrected an earlier claim that the FA2 fork was prefill-only. With FR13_FA2_TREE_BIAS=1, the forked FA2 tree-bias kernel is the deployed decode path; the 0.00195 Triton residual is fallback evidence, not the proof path.

Conclusion: Triton TREE_ATTN remains useful as a diagnostic/fallback, but the published verifier must stay on forked FA2 decode and native FA2 prefill. Receipt.

WY / whole-tree algebra route

open parked

Why it looked plausible: whole-tree algebra can express equivalent recurrent updates over real arithmetic and could reduce the per-node state traffic that makes tree verification expensive.

  • Evidence then: chunked-WY style routes missed the literal-zero bar and introduced summation-tree differences. That made them risky as the proof path.
  • Later correction: the replay route that shipped is not chunked-WY; it is an accepted-chain replay kernel. WY was also never cleanly re-measured under the later within-native-floor bar.

Conclusion: WY is not disproven as a future speed route, but it is parked. The final paper should not present it as failed theorem math; it failed the served-proof gate for this delivery. Receipt.

Replay as the unifying lossless and accept-yield cure

superseded

Why it looked plausible: replay publishes only the accepted path, so it was tempting to believe it would fix both state contamination and the low accept/event traces.

  • Evidence then: the page-stomp bug was real: conv-remap could overwrite the replay-published state with stale or zero blocks.
  • Later finding: after the page-stomp fix, replay produced token-identical behavior to legacy all-rows publish and accept/event around 2.08-2.15. The state-publish change moved accept by zero in that gate.

Conclusion: replay survives as the right publication invariant and a speed/scaling lever, but the "replay fixes accept collapse" framing is superseded. Accept defects had to be localized elsewhere. Receipt.

Literal 0.0 max-abs as the only lossless bar

superseded

Why it looked plausible: bit-identical or max-abs-zero gates are easy to explain and hard to game.

  • Problem: native decode itself has recurrent-oracle numerical floors. A literal-zero gate can reject a route that preserves the sampled distribution within native noise.
  • Later evidence: clean B=1 p-rescore closed native E5 at 12.90%, cat9 at 13.28%, and cat6root at about 13.09%; both tree arms are within native floor by less than one standard error.

Conclusion: "lossless" is formally distribution-preserving within the native recurrent-oracle floor, not bit-identical equality of every intermediate tensor. Receipt.

BV=4 shrink and native-match full-tree BV32/w1/s3

settled

Why it looked plausible: smaller BV reduces branch cache pressure, while native BV32/w1/s3 matches the baseline kernel geometry.

  • BV=4 issue: it changes the reduction/program shape and adds many more programs, so it is not a clean native-equivalence route.
  • BV32 issue: a full tree with N_PAD=16 would require about 256KB of fp32 h_cache in one warp, roughly 2048 fp32 registers per lane, which spills.

Conclusion: the deployed scan stays at BV16/warps8/pad16. Native-match geometry is a correctness probe; recompute/replay is the way to avoid full-tree cache explosion. Receipt.

Multi-spine and copied-state routes

settled

Why it looked plausible: multiple native-like chains can avoid having a single recurrent scan understand a branch tree.

  • Failure mode: these routes duplicate KV/state work and turn the verifier into several expensive linear decodes. That fights the bandwidth-bound regime the tree was meant to improve.
  • Later status: no later clean B=1 result required reviving this route. Once branch-local scan closed, copied-state spines became an implementation fallback, not the main mechanism.

Conclusion: the descriptor can still represent degenerate K-chain cases if a future drafter needs them, but the paper should present tree-scan/replay as the served path.

cat3w and shallow-width probes

settled

Why it looked plausible: shallower trees should reduce recurrent depth, lower scan work, and make the branch cache smaller.

  • Failure mode: shallow width did not recover the depth-5 accept economics. The model's native MTP spine already extracts value from depth; extra shallow siblings can add co-residency cost without enough accepted tokens.
  • Later status: cat6root's clean B=1 win keeps the depth-5 spine and only adds the root sibling, which is a more conservative version of the same branch idea.

Conclusion: the final shape lesson is not "make the tree wide." It is "preserve the depth-5 native spine, then add only branches that survive lossless and speed gates."

cat10 root-sibling expansion

contaminated open

Why it looked plausible: adding one rescue branch to cat9 should improve step-0 rejection without changing the spine.

  • Evidence then: a live add-one-node run dropped accept/event from 3.198 to 2.932, suggesting branch dilution or packing damage.
  • Later correction: the suffix frontier doc marks whether that drop was artifact or partly real as unsettled, and the WY/replay plan pins the cat10 -28 issue to drafter-side S3 rather than verify replay.

Conclusion: cat10 should be quarantined as an unresolved contaminated read, not used as the final branch-economics verdict. cat6root keeps the root-sibling idea in the cleaner B=1 shape. Receipt.

OPT-A fp8 GEMV / propose_tree as the Stage D explanation

superseded

Why it looked plausible: the lm-head/proposer path looked like an obvious speed lever, and earlier Stage D framing treated growing-row proposal work as the likely source of overhead.

  • Later evidence: the Stage D localization shows cat6root uses FR10_CATERPILLAR_NATIVE_SPINE_TOP2, not the old self.propose_tree growing-row path. Extra root top-k is a tiny GPU-side stack of six integers, under 0.1ms/step.
  • Measured facts: verify forward is near equal (0.13798s cat6 versus 0.13704s native), and isolated committer compute is about 0.34-0.35ms.

Conclusion: OPT-A/propose-tree is not the current bottleneck explanation. Remaining Stage D attribution needs direct step-wall phase timing, not another proposer micro-optimization. Receipt.

Per-request TPS and derived +28ms as headline facts

superseded

Why it looked plausible: per-request TPS is a real latency view, and derived per-step deltas are tempting when end-to-end request summaries are easy to collect.

  • Later correction: cat6root is +4% on per-request-equal decode TPS but +27% on token-weighted decode throughput. The per-request view underweights long decode turns, where most generated tokens are.
  • Contaminated framing: the old +28ms cat6-slower statement was a derivation artifact; direct request decode time per draft showed cat6 at 201.9ms versus E5 at 218.8ms.

Conclusion: keep per-request TPS as a latency caveat, but the throughput headline is token-weighted decode. Any Stage D overhead claim needs direct phase timers. Receipt.

B=4 speed read as the primary verdict

contaminated open

Why it looked plausible: serving ultimately needs batching, so B=4 looked like the more deployment-relevant verdict than a clean B=1 mechanism run.

  • Raw diagnostic: B=4 tree returned 18.028 tok/s versus native 41.266, with tree accept/event 2.024 versus native 3.794.
  • Later correction: the tree is a strict superset of native's depth-5 MTP spine. A correct tree verifier cannot accept fewer spine tokens than native. Therefore 2.024 < 3.794 means the read was contaminated by dropping the spine, not a true branch-yield ceiling.

Conclusion: B=4 remains an important deployment gate, but the old B=4 win/loss and break-even arithmetic should be marked contaminated. Clean B=1 is the mechanism proof; B=4 needs a refreshed carrier-clean run. Receipt.

Raw /v1/completions prompt probes

contaminated regime

Why it looked plausible: raw prompt probes are quick to run, deterministic enough for debugging, and cheap compared with a full Codex/SWE deployment measurement.

  • Failure mode: they do not exercise the chat/thinking deployment path, request anatomy, prompt lengths, or vLLM serving surfaces that dominate the actual result.
  • Later status: the result section now uses Codex/SWE deployment traces and separates decode-only throughput from end-to-end wall time.

Conclusion: raw completions probes are acceptable smoke tests, but contaminated as headline evidence. Deployment-regime measurements are canonical.

Suffix/MTP shortcut before verifier closure

refuted

Why it looked plausible: suffix decoding or MTP-plus-suffix could make drafting cheaper, increasing accept/event without putting more weight on the verifier.

  • Later red-team: the "Design A beats native" claim was refuted: the measured analog saturated at A/E 2.94, below native 3.16. The "add equals zero dilution" assumption was contradicted by the cat10 add-one-node drop.
  • Contamination: the old accounting mixed baselines, leaned on a single-draw cat9 number, and was downstream of a still-failing lossless gate.

Conclusion: suffix decoding is valuable after the verifier boundary exists, not before it. The surviving idea is adaptive confidence-gated suffix length downstream of lossless tree verification. Receipt.

Hidden-state substitution localization v1

contaminated instrument

Why it looked plausible: substituting oracle hidden states into selected layers seemed like a direct way to localize where a wrong branch decision became irreversible.

  • Instrument defect: v1 hardcoded forward_row:6, oracle_row:0, and skip:6 without deriving them from the committed token's provenance.
  • Positive-control failure: splicing the oracle through all 64 layers still did not change the measured position, proving the splice never touched the computation being judged.

Conclusion: any "no revert anywhere" or "diffuse accumulation" claim from v1 is invalid. Localization must first prove a positive-control splice at the measured unit. Receipt.

Threats to Validity

Honest scope: the result is strong for clean B=1 decode throughput and distribution-preserving closure within the native floor. It does not claim every deployment bottleneck is solved.
