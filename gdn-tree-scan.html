Volume III - preview for the final paper

Lossless GDN Tree-Scan

How a tree speculative decoder for a 75% recurrent hybrid model turned from a speed hack into a proof stack: native-op-order GDN scan, forked attention kernels, committer wiring, lossless gates, and a measurement harness that kept invalid wins out of the record.

Mark Ma ML systems / inference Qwen 3.6-27B FP8 / GB10 June 2026

Abstract

Vol. II named the wall: a packed tree cannot be made lossless on a Gated-DeltaNet hybrid by attention masks alone. Vol. III is the answer: build the recurrent verifier in the same native-op-order frame as decode, prove every branch against its own path-to-root oracle, and measure speed only after the lossless and measurement gates are non-vacuous.

The preview result is stronger than a kernel sketch. It covers the forked FA2 tree-attention path, the GDN tree scan/replay lineage, committer and durable-state wiring, the big-denominator within-floor lossless evidence, and the current speed frontier: the remaining overhead is largely our tree-propose/committer path, not an unexplained model wall.

The result is a verifier discipline, not one lucky tree shape

The tempting story was simple: run a wider tree, accept more tokens, beat linear MTP. That story failed repeatedly. Packed trees corrupted recurrent state, multi-spine copied too much state, shape changes traded accepted tokens against forward cost, and several attractive numbers vanished under better measurement.

The durable result is the discipline that survived those failures. The verifier must run the same mathematical path as native decode, every published state must be traced through explicit committer wiring, and every speed claim must separate forward time from accept rate and instrumentation tax.

Figure 1Tree speculative decode as a proof pipeline

The key move is not only adding branches. The system is built as a gated proof pipeline: propose a tree, verify each branch in a native-op-order frame, commit only a distribution-safe path, then measure speed in the clean OFF regime.

The GDN kernel problem

Qwen 3.6-27B is a hybrid: 48 of 64 layers are Gated-DeltaNet recurrence. Attention masks solve the 16 softmax layers; they do not solve the recurrent layers, because recurrence carries hidden state in sequence order. A flattened tree makes sibling rows visible unless the scan is made path-local.

The working rule became strict: no shared recurrent accumulator across branches, no full-state copy per spine, and no algebraically equivalent form unless it follows the native numerical order closely enough to survive the gates.

Physical constraint

On GB10, decode is weight-bandwidth-bound. Moving extra recurrent states through HBM can dominate a mathematically elegant kernel.

The published page should therefore price both correctness and state traffic, not just FLOPs.

Figure 264-layer hybrid model: 48 recurrent layers, 16 attention layers
Gated-DeltaNet recurrence: 48 layers Softmax attention: 16 layers

This composition is why Vol. II's attention-mask-only view was insufficient. The recurrent majority needs a tree-aware scan, replay, or native-basis WY path.

GDN recurrence, per value head
S_t = g_t * S_{t-1}
delta_t = beta_t * (v_t - (g_t S_{t-1}) k_t)
S_t = g_t S_{t-1} + delta_t k_t^T
o_t = S_t q_t
Tree rule: node state must equal native recurrence on exactly that node's root-to-node path.
Rejected

Shared packed tree

One flattened tree with one recurrent state corrupts branches. Attention masks cannot hide sibling updates from the GDN accumulator.

Rejected

Multi-spine copies

Running real co-scheduled sequences can be correct, but full state copies do not scale and produced no speed crossover on bandwidth-bound hardware.

Viable

Native-basis WY tree

Compact factors carry branch-local path products without per-node full-state copies. CPU validation hit fp32 4.19e-9, 0/9 argmax flips.

Shipped route

Scan plus replay

The scan verifies nodes; the replay route re-executes only the accepted chain for durable state. The main change is state logistics, not verifier math.

The attention kernel and wiring work mattered as much as the GDN scan

The final paper should not make the GDN kernel look isolated. The recurrent scan only becomes useful when the attention half, conv state, replay route, and committer agree on the same path semantics. Much of FR13 was spent proving which front was actually guilty.

Full attention

Forked FA2 tree-bias decode path

The tree-attention path moved through CUDA-graph capture and FA2-floor checks instead of accepting "within floor" as a hand-wave. The deployed decode path uses the forked FA2 tree-bias kernel for tree rows.

Conv state

Committed-path prior window

Several apparent GDN defects were wiring defects. The conv prior window had to be gathered from the accepted leaf column before remap mutates the bank.

Replay

Page-safe remap after byte gates

The replay kernel passed byte A/B gates, then failed live until a page-stomp in conv remap was pinned and fixed. Offline-bit-identical was necessary, not sufficient.

Committer

Device-side multidraft committer

At temperature 0.6, host-side multidraft commit became the real deploy lever. Device-side commit recovered about 22% against the host reference before later profiling reframed the remaining overhead as our tree-propose/committer path.

The measurement infrastructure is part of the contribution

The project repeatedly found that attractive numbers were not wrong because the model was mysterious; they were wrong because the measurement basis was contaminated. The canonical infra turns those failure modes into explicit gates.

s/fwd = d(request_decode_time_seconds_sum) / d(spec_decode_num_drafts_total)
accept/event = d(spec_decode_num_accepted_tokens_total) / d(spec_drafts)
committed/event = accept/event + 1
TPS = committed/event / s/fwd [derived, never the source basis]
Separated

OFF speed vs ON lossless

Clean deployment speed runs with instrumentation off. Lossless captures run separately because q-capture and oracle probes add real tax.

Fixed

Matched denominator timer

The GPU decode-forward timer now divides by drafts on timed pure-decode steps, not global drafts that include mixed prefill/decode steps.

Re-aimed

B=4 to B=1 switch

B=4 per-forward comparisons were concurrency-confounded. B=1 removes co-residency while preserving temp-0.6 deployment behavior for arm comparison.

Audited

Trust ledger

Each number is tiered by prompt regime, temperature, batch, and source basis. Contaminated accept numbers are not allowed to become paper claims.

The speed story is now sharper: the remaining delta is ours to profile

After the lossless chase, the speed work became a series of falsifiable attempts. Some fixed real overhead. Some did nothing. Some produced false wins that the measurement harness rejected. That is the scientific value of the trail.

Attempt Result Decision Lesson
FIX-1/2/3 speed lineage cat9 1.40x -> 1.03x s/fwd stands Double lm-head, eager packing, and conv fusion were real removable overheads.
OPT-A GB10 fp8 GEMV config 0.2440 vs 0.2436 s/fwd neutral Tree-verify GEMM was not the deployment bottleneck.
cat6root reshape 17.61 TPS vs cat9 18.47 no ship Fewer rows saved forward time but lost accepted tokens.
cat10 root sibling 18.31 TPS vs cat9 18.47 neutral Root sibling added accept, but the extra verify row offset the gain.
OPT-1 committer sync-kill EngineCore crash from dispatch composition bug fixable CPU byte gates missed live in-process dispatch; the defect was located, not dismissed.
Overhead profiling frontier about +0.026 s/step delta next Because native E5 and cat6 share stock pieces at B=1, the remaining delta is our tree-propose/committer path to tune.

The final-paper speed section should not claim victory from a single throughput bar. It should show the decomposition: verify-forward cost, tree-propose cost, committer cost, and fixed scheduler gap. The latest branch explicitly reprioritizes profiling and tuning the device committer plus tree-propose path before adding more shapes.
