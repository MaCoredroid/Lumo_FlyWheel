Lossless GDN Tree-Scan

A tree speculative decoder for a 75% recurrent hybrid model. The core result is not a wider attention mask; it is a branch-local Gated-DeltaNet scan, a forked attention path, vLLM committer wiring, and a measurement stack that separates losslessness from speed.

TL;DR: a draft tree is a menu of next-token guesses. The target model verifies that menu and publishes only the accepted prefix. On this 75% recurrent model, that requires tree-aware attention plus branch-local GDN state; attention masks alone are not enough.

Abstract

We present a lossless tree-scan verifier for tree speculative decoding on Qwen 3.6-27B-FP8, a hybrid model whose 64 layers include 48 Gated-DeltaNet recurrent layers and 16 softmax-attention layers. The problem is that a token tree is not only an attention-mask problem. Each candidate row must carry the GDN state that native decode would have produced along exactly that row's root-to-node path.

Our implementation combines a forked FlashAttention-2 tree-bias path, a Triton GDN tree scan/replay kernel, vLLM tree-shape packing, device-side multidraft commit, and deployment-mode measurement gates. In the latest clean B=1/temp-0.6 deployment run on four SWE/Codex tasks, both depth-5 tree shapes beat native E5: cat9 reaches 18.44 tok/s and cat6root reaches 18.51 tok/s versus 17.80 tok/s for native E5. Cat6root is the cleaner winner: 3.82 accepted tokens/event with essentially native verify-forward time, 0.1377 versus 0.1370 seconds per forward.

Contribution

This preview treats the result as a systems proof, not a benchmark-only result. The contribution is a way to verify token trees for a recurrent hybrid model while keeping the target distribution tied to native decode.

Earlier pages covered the search arc. This page is self-contained: it states the problem, names the prior work, shows the kernel invariant, explains the hardware limitation, and gives the final B=1 speed numbers now merged to main.

Prior Work

Speculative decoding: a cheaper draft path guesses future tokens, then the full model verifies them. If the verifier rejects a guess, the algorithm falls back without changing the target distribution.

Tree decoding: instead of one draft chain, the draft proposes several possible branches in one verification pass.

Tree speculative decoding is well studied for Transformer-style attention stacks. SpecInfer introduced tree-based speculative inference and parallel verification while preserving model quality. Sequoia made the tree shape hardware-aware. EAGLE-2 uses context-aware dynamic draft trees while keeping the output distribution unchanged. OPT-Tree frames the tree shape as an acceptance-versus-overhead optimization problem.

The closest prior work for this project is STree, which studies speculative tree decoding for state-space and hybrid models by exploiting accumulated state-transition structure. Our work targets a different deployment surface: Qwen 3.6-27B in vLLM, with Gated-DeltaNet layers, forked FlashAttention-2 tree bias, a Triton GDN scan/replay kernel, device-side multidraft sampling, and deployment-mode speed/lossless gates.

Kernel and Math

GDN: Gated-DeltaNet is a recurrent layer. It carries a state tensor forward through the sequence.

Native path: the exact token order ordinary decode would have seen. A tree node is valid only if its recurrent state equals the native decode state for that node's branch path.

Qwen 3.6-27B is not an attention-only stack. Its recurrent layers mean that a tree verifier must compute one state per branch path. Sharing a single recurrent accumulator across flattened tree rows is wrong, because sibling rows would inherit state from branches that native decode would never have visited.

The kernel invariant is simple enough to state and hard enough to implement: for every node i, the state S_i used by the verifier must equal the native GDN recurrence evaluated over the tokens on path(root -> i).

GDN recurrence, one value tile
S'_t = exp(g_t) * S_{t-1}
delta_t = beta_t * (v_t - S'_t k_t)
S_t = S'_t + delta_t k_t^T
o_t = S_t q_t
Tree invariant: S(node i) == native_scan(tokens on root-to-i path)
Figure 1What the GDN tree scan does

The scan verifies the whole candidate tree. The replay route re-executes the accepted chain and publishes durable state. Rejected branches are evidence for the committer, not future model memory.

Why BV and h_cache limit the kernel

BV is the value-channel tile width, called BLOCK_V in the Triton kernel. One program holds a GDN state tile with shape [BV, DIM_K]. A tree scan needs a post-state for every padded node because each child must select its own parent state. That is the h_cache: [N_PAD, BV, DIM_K] in fp32.

This is why native-match geometry does not scale directly. Native decode uses BV32 / num_warps=1 / num_stages=3. A full tree with N_PAD=16 at that geometry would demand about 256KB of fp32 h_cache in one warp, roughly 2048 fp32 registers per lane, which spills. The deployed tree scan uses BV16 / warps=8 / pad16 to fit. Native-alignment experiments use recompute/replay with one [BV, DIM_K] tile instead of caching every node.

Fresh-reader translation

BV is how wide a slice of model memory the kernel handles at once.

h_cache is a table of branch memories. More nodes make the table bigger. If the table is too big, the GPU spills registers into slower memory, and the "correct" kernel stops being fast.

Tree scan pseudocode
for node in sorted_tree_nodes:
  parent_state = b_h0 if node.parent is root else h_cache[node.parent]
  out, state = gdn_node_step(parent_state, token_features[node])
  h_cache[node] = state
commit: replay accepted spine in native order, then publish state

How the Kernel Connects to Attention and vLLM

FA2: FlashAttention-2. The attention layers need a tree-aware bias so each row sees exactly the ancestors it should see.

vLLM wiring: the page-level result depends on scheduler metadata, slot mapping, draft packing, sampling, and state publication matching the same tree.

The GDN scan is only one piece. The shipped tree path has to align five surfaces: the draft tree choices, the forked attention kernel, the recurrent scan/replay kernel, the multidraft committer, and the durable state writeback. Most of the engineering effort was chasing cases where one of those surfaces agreed with the shape but disagreed with the path semantics.

Figure 2vLLM decode path with tree verification

The tree shape is a contract. The drafter, attention metadata, recurrent scan, committer, state replay, and metrics all consume that contract. A mismatch at any boundary can look like a model-quality issue until the gates isolate it.

Attention

Forked FA2 tree bias

Softmax-attention layers use a tree-aware bias path so candidate rows attend to ancestors, not siblings.

Drafter

Single-logits packing

The root and spine tokens are taken from the same logits tensor; runner-up leaves are top-k reads, not extra model forwards.

Committer

Device multidraft path

The temp-0.6 committer moved the SpecInfer residual-mix rule onto device to remove full-vocab host softmax transfer and Python per-node loops.

State

Replay before publish

The accepted chain is replayed in native order before durable GDN/conv state is written. Rejected rows must never become future state.

The Tree Shapes: E5, cat9, and cat6root

cat9 / cat6root: nicknames for fixed token-tree menus. They are not new models.

Path notation: (0,0,1) means follow top-1, then top-1, then the runner-up at that depth.

The latest speed result compares a native depth-5 linear speculative path against two depth-5 trees. cat9 is wider: the spine plus runner-up leaves at depths 1 through 4. cat6root is smaller: the full depth-5 spine plus only the root sibling. The surprise is that cat6root wins cleaner at B=1 because it keeps almost all of the accept gain with essentially native verify-forward time.

Latest B=1 Result

B=1: one request stream. This removes co-residency noise that can hide whether the tree itself is faster.

s/fwd_gpu: decode-forward GPU active time per verify event. It isolates the verifier from accepted-token arithmetic.

The merged B=1 depth-5 result uses four SWE/Codex tasks, temp 0.6 forced, vLLM-only GB10 deployment, and the matched pure-decode GPU timer. The result is not just that a tree beats native. Both cat9 and cat6root beat native E5, and cat6root is better on the clean axes that matter for the next optimization pass.

Arm Tree Deploy TPS Delta vs E5 s/fwd_gpu Accept/event Committed/event Readout

The decomposition is the important paper point. cat6root commits 4.821 tokens/event versus 4.112 for native E5, a 17.2% committed-token gain. Its verify forward is essentially native. The net TPS gain is only about 4.0% because the remaining per-step overhead comes from our tree-propose and committer path.

Measurement Infrastructure

OFF speed / ON lossless: speed runs disable heavy probes. Lossless runs enable oracle capture. Mixing them creates fake speed regressions or fake wins.

p-rescore: an offline check that compares the tree path against the recurrent native oracle for the final sampled setting.

The measurement stack is part of the contribution because several plausible wins were rejected by better instrumentation. The canonical rule is to measure deployment speed with probes off, then measure losslessness with probes on, and never let raw prompt-mode tests replace the real vLLM/Codex deployment path.

s/fwd_gpu = decode_forward_gpu_seconds / pure_decode_drafts
accept/event = accepted_tokens / draft_events
committed/event = accept/event + 1
deploy_TPS = request_decode_tokens / request_decode_seconds
Speed basis

Deployment path only

The paper numbers use the real Codex/SWE vLLM path, not raw /v1/completions prompt tests.

Timer basis

Matched pure-decode denominator

s/fwd_gpu divides by timed pure-decode drafts, avoiding mixed prefill/decode denominator drift.

Lossless basis

Separate oracle mode

The merged speed verdict still asks for the depth-5 E5/cat9/cat6 p-rescore gate before the final paper treats losslessness as closed for this exact run.

Profiling basis

The remaining delta is ours

At B=1, native E5 and cat6root share stock pieces. The extra roughly 0.026 seconds/step is therefore our tree-propose/committer path to split and reduce.

Lossless Evidence and Open Gates

Lossless does not mean similar text. It means the speculative path preserves the target model distribution, up to native numerical floor.

BV A/B: a scan-only check showing whether different value-tile settings change the branch decision in a controlled regime.

The lossless chase found both numerical and wiring failure modes. A key lesson was that scan-only bit-exactness is not enough. BV A/B showed the scan op itself can be native-stable in a shallow single-forward regime, but live decode also feeds recurrent state through co-resident accepted chains, committer publication, conv prior windows, and deep attention layers.

What the Final Paper Emphasizes

The clean story is not "tree speculation is faster." The clean story is that lossless tree verification on a recurrent hybrid model has a different systems contract than Transformer-only tree verification. We had to align attention, recurrent state, sampling, durable state publication, and measurement before the speed result became credible.
