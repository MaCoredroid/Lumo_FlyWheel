# Penalty-history fix: re-qualification and re-measurement (2026-10-03)

**Defect (found 2026-10-02, `sampling_correctness_20261002.md`):** vLLM's `_combine_outputs_with_spec_tokens` gives verification row j the chain history `output + spec[:j]`. TreeHost verifies a tree: target row j is the distribution at parent(j) and the tree self row j the distribution at node j, so with `presence_penalty=1.0` every decision past the root was penalised against sibling and off-branch tokens (2,480/2,480 captured rows flattened; per-node TV up to 0.42).

**Fix (`FR13_TREE_PENALTY_HISTORY`, treehost-v2exp `9902ccca2`, mirrored in the PORT tree `bdfdb596f`):** the production patcher adds a tree-aware combiner to `rejection_sampler.py` that builds per-path histories from `metadata.tree_parent_indices` (31 draft-space parents per tree request, request-local, root -1; validated, cached, fails loud on a malformed table) and a method `apply_logits_processors_tree_self` through which the runner's tree-self-row calls are routed (row j there additionally contains node j's own token). Chain requests keep the stock combiner. Native arms are untouched.

Pre-flight on CPU (`penfix/test_tree_history.py`): synthetic trees (B=1 and a mixed batch with a draft-less request); on the 2 Oct capture the chain prediction reproduces the defect 2,480/2,480 and the fixed combiner matches the per-path history 2,480/2,480; the patched stock sampler compiles with the existing handoff patches.
