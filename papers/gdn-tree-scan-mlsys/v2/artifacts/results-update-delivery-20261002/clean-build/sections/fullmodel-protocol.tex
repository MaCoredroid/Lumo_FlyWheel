The continuation comparison uses five fresh serving processes: sequential reference $A$, an independent repeat $B$, a native cache-capacity control $V$, a native packed-GDN-kernel variant $P$, and \sys{}. The reference uses a 40\,GiB KV allocation; $V$ uses the candidate's observed allocation. Candidate capacity follows its deployed memory-fraction policy. All arms import the same recurrent, convolution, and attention starting state once per schedule, consume matching forced tokens and positions, and retain their own published state thereafter. This control distinguishes continuation differences from differing natural prefills without requiring identical cache bank geometry.

The seven prefixes comprise three calibration prefixes, three evaluation prefixes, and one cache-boundary prefix. Thirty-three schedules cover principal and off-spine paths, root-only continuation, correction and bonus tokens, deep branches, and page crossings over four to seven cycles. A terminal flush consumes the final pending token. Candidate-input checks compare all 32 verification rows with the forced tree. An earlier collection whose forcing was shifted by prefill drafter calls is retained as invalid and contributes no reported comparison quantities.

Five fault types run on two calibration prefixes each: omitted convolution gathering, omitted recurrent replay, incorrect KV remapping, stale root input, and sibling-state publication. Faults are injected at the second cycle and checked on their targeted surfaces. The frozen comparator uses a fourfold native calibration envelope and requires every fault observation to be detected. Its result and the separately disclosed post-hoc analysis are both preserved in the supplement; the latter does not replace the former.
