The replay corpus contains 43 requests recorded from the Astropy tasks \texttt{12907} and \texttt{13033}. Each configuration receives the same saved messages and tool definitions, sequentially with at most one active request. Reported vLLM prompt lengths range from 23,024 to 68,557 tokens. Sampling uses temperature 0.6, top-$p$ 0.95, top-$k$ 20, and presence penalty 1.0, with a 1,024-token response cap and no per-request seed. This protocol measures fixed-request serving behavior; it does not rerun either coding task.

Native autoregressive decoding, chain MTP, and \sys{} use the same checkpoint, vLLM image, tokenizer, chat template, and common serving settings, including prefix caching, chunked prefill, a 131,072-token context limit, and one active sequence. The native arms use their native attention invocation; \sys{} uses its specialized tree-attention path. SGLang EAGLE uses the same checkpoint and saved request files, with FlashInfer attention and its own serving and tool-parsing implementation. Although both stacks receive the same chat-template file, SGLang reports 146 additional prompt tokens per request. Whether this difference comes from serialization or token accounting remains unresolved.

The replay client measures time from the first nonempty streamed content, reasoning, or tool-call delta to stream completion. We apply Eq.~\ref{eq:pooled-decode} to these client durations and server-reported completion counts, pooling matched token and time totals across requests and repetitions. The estimate excludes first-output latency and server startup. Subsequent stream delivery and parser behavior remain in the measured duration.
