## Exact input and hook placement

Native Eagle `set_inputs_first_pass` at 657–675 shifts token IDs left, inserts the externally supplied next token at the selected request tail, keeps positions unchanged, and copies matching target hidden rows. Thus a prompt split into chunks is supported **if every consumed target row is observed**. For prompt `[11,13,17,19]` split into two length-two chunks, followed by forced root `23`, MTP receives `[13,17]` at positions `[0,1]` with the first two target hidden rows, then `[19,23]` at `[2,3]` with the next two rows. The partial-prefill sampler's arbitrary output must never replace the actual next prompt token.

- At real pre-forward, join one actual request and case, owner/allocation generation, scheduler object, `ncomp`, positive `n_sched`, fixture prompt digest, and the exact prepared IDs/positions. Require initial `ncomp == 0` and subsequent `ncomp == prior_ncomp + prior_n_sched`; no gaps, replay, preemption/restart, or request substitution may silently reuse history.
- Capture `hidden_states[qsl:qsl+n_sched]` at the native post-forward/pre-logits-gather seam (runner 4070–4071), before narrowing to only `logits_indices`. Clone that slice and its matching pre-forward IDs/positions; reject padding, row-count, width, position-axis, or step mismatch. B1 does not justify using the whole padded buffer.
- For `after = ncomp+n_sched < prompt_len`, the next ID is exactly `prompt_token_ids[after]`. The existing hook returns early here, so the history call must not be placed after that return. At prompt completion and chain decode, use the token after the existing teacher-force write. Record that actual next ID and its source.
- The existing terminal `on_sampled` branch seals immediately after forcing the terminal token. All declared MTP observations and pending follow-up obligations must be resolved before a valid terminal seal; simply appending work after the existing hook would produce incomplete seals.
- `Program.first` currently retains `live` after every first pass. Normal noncheckpoint steps need an explicit validated completion operation that releases pending Python context without resetting persistent KV. Only declared checkpoints retain a live follow-up. Do not silently clear an unconsumed checkpoint to admit another first pass.

The real metadata arm/disarm proposal uses the correct seam: runner 3969–3986 calls `_build_attention_metadata` with `scheduler_output.num_scheduled_tokens`, while dummy 5431–5440 does not. Arm immediately around that one real call, disarm in `finally`, fail-stop on any builder/capture exception, and consume only with the identical scheduler object and matching request/step/generation. A noncapturing dummy must neither overwrite an armed real capture nor be accepted as a real one. There must be exactly one captured MTP group, not an optional last-seen value.

## Cache salt and cold independent history

The accepted native smoke attests `enable_prefix_caching=true`; therefore missing-prefix history is a real protocol consideration. The new mandatory initial `ncomp == 0` is appropriate for this bounded independent-history stage. Reused/APC history remains unsupported unless separately authenticated; registration of MTP alone does not make skipped hidden rows or its shifted-input history available.

The exact native engine input processor transfers `decoder_inputs.get('cache_salt')` at line 369. Exact `kv_cache_utils.py:518–527` puts a nonempty salt in the first block's extra hash keys, and `:559–562` chains each subsequent block hash through its parent. A unique prospectively bound per-observation salt can therefore isolate the prefix-cache namespace while leaving the engine's APC setting enabled. However the retained sources do **not yet establish `/v1/completions` request-schema acceptance and its preprocessing propagation**; the existing driver uses that endpoint. Before relying on this, bind the exact completion protocol/serving path and actual received salt, and retain the runtime `ncomp == 0` check. Missing/ignored/empty/reused salt must not turn unexplained APC reuse into valid history. This is a prospective calibration policy; it does not retroactively relabel the old corpus or qualify APC reuse.

## Deferred follow-up and restoration

The proposal correctly preserves native semantics by deferring only execution time, not inputs. Native follow-up uses the **first-pass MTP output hidden**, first natural draft token, and incremented MTP position (`eagle.py:487–492,545–638`). It must not consume newly computed target hidden or replace retained sequence lengths with the next target step's values.

At the next real target pre-forward, prove the required destination belongs to that same request and allocation generation. Use the actual allocated kernel-block count and block table, not merely a nonnegative value in a padded table. Require all previously allocated prefix mappings and the retained cache identity to remain unchanged. Refresh only the retained common metadata's authenticated block table; native follow-up increments the old sequence/query metadata itself. Distinguish 1024-token allocator pages from 64-token kernel blocks: crossing a kernel block within an allocated page requires no extra allocation. If the request ends before the needed slot exists, report the obligation as unexecuted and refuse a complete seal.

Before the speculative follow-up, save both K and V bytes for its exact physical slot and authenticate the cache object/strides, group, position, and page conversion. After recording full follow-up logits, restore those exact bytes before the next teacher-forced first pass and verify restoration. A failure after a cache write cannot be caught and treated as an ordinary missing observation; the owner must fail-stop. Do not restore or recompute the whole prefix, reuse a new target hidden row, or retain a speculative KV row as teacher-forced history. Existing graph padding must map only the genuine follow-up row to storage; padding remains unwritten.

## Minimal record and focused controls

A valid case needs explicit expected and observed step coverage, request/case/fixture/owner bindings, actual shifted IDs and all position axes, selected hidden rows, cache extent/group/block-map lineage, finite full-vocabulary first/follow logits, exact smallest-ID argmax, tie count/margin, and the predeclared ordered top-k rule. Preserve native `torch.topk` ordering at ties; do not silently replace it with a custom smallest-ID ranking or use a margin exception. Partial-prefill history steps and declared evaluation checkpoints must be labeled separately, not inflated into additional experiments.

The smallest meaningful CPU wiring controls are: two unequal prompt chunks with distinct next-prompt/forced IDs; padded hidden-row exclusion; wrong or skipped initial offset; dummy/real metadata crossover and builder failure; noncheckpoint completion versus retained checkpoint; next-slot allocation at the 1024 boundary; unchanged-prefix-map refusal; exact follow-up K/V restoration and restore failure; and terminal sealing with a missing MTP obligation. They validate the proposed connection without changing numerical criteria or requiring new GPU experiments.
