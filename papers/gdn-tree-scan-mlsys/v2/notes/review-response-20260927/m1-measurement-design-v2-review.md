# M1 measurement/qualification proposal v2: scientific design review

**Disposition: amend before implementation/freeze.** The proposed finite repetition schedule is usable for a first fixed-geometry measurement substage. Its present gate establishes reproducibility, not numerical qualification, and its proposed aggregate omits required work. These are design corrections; no new broad experiment campaign is needed.

## Minimum necessary corrections

1. **Separate numerical eligibility from reproduction of an observed result** (proposal §5). Bit-exactly repeating the initialization outputs would also repeat a deterministic wrong implementation. Retain that check as a reproducibility control, but do not call it qualification. Before any timed comparison, name the independent numerical reference, operator policy, compared output/state surfaces and a prospectively frozen acceptance rule. Reuse the already frozen Q1 paired numerical rule only where its named operator, input policy, grouping and surfaces actually apply; do not silently transplant its multiplier/floor to a different author policy. Where applicability is missing, obtain baseline-only calibration and freeze a bounded rule and evaluation cases before new candidate qualification. The already observed seed-20260928 case remains a reproduction/diagnostic case; its observed candidate errors must not determine a new acceptance envelope. Preserve exact structural/finiteness controls and already required negative controls. No numerical threshold is proposed here, and an implementation without an applicable frozen rule remains diagnostic-only rather than being declared qualified by repeat matching.

2. **Replace policy names with a small explicit arithmetic contract** (§1). Bind normalization formula/epsilon or clamp, q/k arithmetic and stored dtype, scale placement, gate/softplus precision, beta storage/casts, accumulation/dot policy, and publication semantics. Weaver author-default verification and replay have different beta-rounding surfaces, so one undifferentiated “author-default sequential replay” does not define both references. Distinguish native, aligned-local and each author-default policy explicitly. A policy-specific implementation check and equivalence to the common native deployment policy answer different questions. Keep cross-policy C2 discrepancies as diagnostics; do not infer an algorithmic defect from them. Drop the promised additive “state scale/normalization term separated from residual” unless a precise identity and executable reference are supplied: cumulative nonlinear recurrence/rounding effects are not generally separable into that scalar decomposition. Reporting the actual policy and independent reference errors is sufficient and cheaper.

3. **Make the complete-cycle aggregate include all required per-cycle work** (§§2–3). Use the authenticated order: reset outside the measured unit; build/preparation as declared; verify then publish each step for Lumo/Weaver; TreeWY's prior-commit/next-verify rounds and final deferred flush. Required gather/remap, normalization, casts, stash writes, metadata updates, temporary-state handoffs, replay and any per-cycle allocation belong in the primary total. The existing plan explicitly requires these costs. An optional compute-only subtotal may exclude them, but cannot be presented as complete-cycle latency or used to rank complete methods. Distinguish reusable topology/setup from per-cycle work using the same workload reuse assumption for all methods. Report one-time setup and warmed steady-state complete-cycle costs separately, or declare the exact finite amortization denominator. Different implementation reuse policies can remain real system differences; they cannot silently change which necessary work the headline includes.

4. **Use synchronized host wall time for the primary cycle and CUDA events as supplementary device measurements** (§3). Events bracket stream progress, not a reliable accounting of host metadata construction, allocator behavior or CPU submission; idle gaps depend on when work is submitted. A whole-cycle wall bracket with device synchronization at its boundaries captures the actual host/device path. Do not insert synchronization after every phase into the primary run. If phase attribution needs an instrumented pass, label it separately; its totals need not equal the minimally instrumented cycle. TreeWY's fused prior-commit/next-verify wrapper is one measured bucket; do not manufacture disjoint verify/publish timings or count the same wrapper twice. Record peak allocated/reserved scratch and available compiled-kernel register/shared-memory/spill metadata, as already required by §4; label logical bytes as computed rather than measured traffic.

   The v3.2 collector performs CPU copies, digests, per-call inspection and raw serialization inside its diagnostic control flow. Timing that observer-heavy path would measure the collector. Move audit-only hashes, reference calculations and serialization outside the interval; use the same callable sequence and argument/representation bindings in qualification and measurement. Required algorithmic copies and serving-path synchronization stay charged. A small measurement mode with call/argument parity checks is enough; an independent rewritten algorithm is unnecessary. Archive the untimed qualification evidence once and retain per-repeat scalars, failures and lightweight execution evidence rather than serializing all raw tensors inside every timed cycle.

5. **Clarify the finite repetition/reset unit and retain original scope controls** (§4). W=2, R=5, forward/reverse blocks is a reasonable bounded starting schedule for this fixed case. Reset the same S0, stashes, sentinel/pending-publication state and relevant counters outside every repeat; preserve intended warmed allocator/JIT state. Do not let previous cycles' durable state accidentally become the next repeat's input. Make the extra qualification cycle explicit: either use the first untimed warmup for the stated reproduction check or increase the stated 56-cycle count; do not hide additional cycles. Define deterministic-repeat handling before execution rather than retrospectively explaining a mismatch as nondeterminism. Retain every scheduled result/failure with its order; a stopped arm must not disappear from the denominator or leave a selective overall winner.

   This fixed-32, L48/B1, one-seed, acceptance-length-1/5 case does not exhaust approved §4. Keep the existing chain/branch controls, accepted-length variation and representative dimensions on the M1 completion checklist, reusing already bound fixtures and matrices. B4 remains optional component sensitivity. Do not add new Bole/SpecLA variants without verified executable source. These controls need not be bundled into the first timing substage, but that substage cannot close all M1 claims.

6. **Derive the memory gate from worst-live allocation, not twice an arbitrary minimum** (§5). The successful initialization observed 12.048 GiB free against a 12 GiB policy. The 0.048 GiB difference is headroom over the policy threshold, **not measured headroom over the workload's peak requirement**. It neither justifies 24 GiB nor proves 12 GiB sufficient for a changed measurement lifetime. Establish a source-based live-allocation bound including persistent banks/graphs, staged inputs, scratch, disposable warmup clones, event/capture buffers and any simultaneously retained CPU tensor data on GB10's unified memory. Use maximum per-method demand only if lifetimes are actually disjoint; otherwise include retained state from prior methods. Add explicitly justified runtime/context overhead and uncertainty, not a margin inferred from observed numerical or timing outcomes. During the already planned untimed qualification/warmup, record allocator allocated/reserved peaks plus driver free-memory/host-available observations, since allocator counters alone omit other allocations and retention. That instrumentation can validate the bound without a separate broad memory experiment. Insufficient resources mean refusal; no implicit reclaim or smaller configuration follows from this review.

## Practical next step

Prepare a short CPU-only amendment containing: (a) each arm's arithmetic/reference identity and applicability of an existing numerical contract or its specific unresolved baseline requirement; (b) the complete-cycle boundary and one-time/per-cycle work ledger; (c) exact repeat/reset counts and the worst-live memory estimate. Keep the existing four methods, fixed geometry, W/R/order and raw initialization evidence. Reuse the accepted launcher/collector provenance and failure-retention work rather than rebuilding them.

Then perform only the already authorized qualification work needed by those explicit contracts, under the parent's existing gates. After it passes, the proposed small forward/reverse timing block can be the first complete-cycle measurement substage. The remaining §4 controls stay finite follow-ons tied to the intended mechanism claim, not a search for a favorable workload. Existing Q1/M1 prerequisites and independent gate ownership remain in force; this proposal's within-run hash check cannot replace them.

The initialization already proved the four call paths and their publication endpoints execute. It did not freeze a numerical tolerance, establish drop-in policy equivalence, validate a timing instrument, or measure peak memory. Preserve that useful bounded outcome without turning it into one of those stronger claims.
