# Native Qwen3_5MTP adapter: bounded source readiness

29 September 2026. Source inspection and AST comparison only; no imports of model code, model execution, GPU, SSH, implementation changes or qualification result. This note supplies the missing adapter contract identified in `q1-fullmodel-reference-design-review.md`; it does not reopen the accepted component results.

**Recommendation:** reuse the pinned native `Qwen3_5MTP` model through the native proposer loading/input/metadata seams in a separate reference worker. Add a small owner of persistent MTP KV and explicit teacher-forced input history. Do not reimplement the layer mathematics, invoke the entire patched tree proposer as the reference, or assume a spec-off target runner already contains an MTP model/cache. The difficult connection is persistent cache and history alignment, not availability of the one-layer implementation.

## Exact reusable model and input contract

1. **One full-attention MTP layer.** Config line 96 fixes `mtp_num_hidden_layers=1`; hidden size is 5120, vocabulary 248320, 24 attention heads, four KV heads, head dimension 256. `R/model.py:57–116` creates `Qwen3_5MultiTokenPredictor`: token embedding and hidden input receive separate RMSNorms, concatenate in **embedding, hidden** order, pass through the 2H-to-H projection, then one `Qwen3_5DecoderLayer(layer_type="full_attention")`. It is not a GDN recurrence. The inherited native attention includes Q/K normalization, RoPE, gated attention output and output projection (`R/.../qwen3_next.py:194–310`); a generic attention or unquantized FC substitute is not this model.

2. **Hidden input and return are not interchangeable with EAGLE auxiliary tensors.** `R/model.py:121–157` takes the preceding target hidden tensor on the first pass, applies its own pre-FC norm, and returns a **single final-normalized hidden tensor**. At the subsequent draft step, the previous MTP-returned hidden becomes the input hidden. Do not unpack `(last_hidden, hidden)` for method `mtp` (`R/eagle.py:825–826`), add another external norm, feed logits, or concatenate EAGLE auxiliary layer outputs. The runner uses the selected model hidden rows unless the auxiliary-output mode is explicitly configured (`N/...gpu_model_runner.py:4660–4721`); record and assert the actual mode. Non-last pipeline ranks return `IntermediateTensors`, so the deployed pipeline setting must remain explicit rather than relying on a tuple-shaped convenience shim.

3. **First pass shifts tokens, not positions or hidden rows.** The no-extra-slots branch of `R/eagle.py:646–678` / `T/eagle.py:6745–6778` performs `input_ids[:n-1] = target_token_ids[1:]`, then writes `next_token_ids` at each `token_indices_to_sample`; absent explicit indices it uses `query_start_loc[1:]-1`. It copies target positions unchanged (apart from the declared position-axis conversion) and copies target hidden rows unchanged. Thus the selected row pairs the preceding target hidden/position with the sampled pending token. Advancing its position early is incorrect. Ordinary request-tail overwrites remove cross-request token-shift contamination. For a tree, the patched proposer instead derives the sample row from the actual accepted physical path's final node (root row 0 when accepted length is zero), plus the request's query offset: `T/eagle.py:615–797`, especially `:759–795`. Accepted length is **not** the selected physical row ID.

4. **Follow-up draft call advances one position and retains cache.** `R/eagle.py:543–641` and `T/eagle.py:5193–5280` consume the previous draft ID cast to int32, run `eagle_step_update_slot_mapping_and_metadata`, update sequence-length shadows, build metadata for the next draft index, and consume the preceding MTP hidden. Use that existing update mechanism rather than independently incrementing position and slot state inconsistently. A new zero cache for every call would erase the very continuation being tested.

5. **Typed callable seam.** Persistent proposer IDs are int32, position buffers int64, hidden/embedding buffers use the loaded model dtype (`T/eagle.py:296–332`). Position shape follows the **draft** model's `uses_mrope` / xD-RoPE settings: either 1-D or all relevant axes, even for text. Do not infer a 1-D shape from the task being text-only. `build_model_inputs_first_pass` (`R:780–809`, `T:6879–6908`) supplies either actual IDs with `inputs_embeds=None`, or `input_ids=None` with embeddings from `model.embed_input_ids` when its multimodal-capable path is active; both also receive `positions` and `hidden_states`. The callable is `model(**kwargs)` within the correct forward context, followed by `model.compute_logits(selected_returned_hidden)` (`R/model.py:424–443`).

## Loading and independent KV ownership

**Use the model loader seam, not a bare Python constructor plus an arbitrary state dict.** Native `_get_model` (`R/eagle.py:1272–1286`, `T:7520–7534`) calls vLLM `get_model` with the resolved draft model/load configs, under the `eagle_head` model tag. `load_model` discovers the draft attention layers by the before/after layer-name difference, then shares target embeddings and the target output head (`T:7536–7617`). For MTP, sharing is unconditional when the stated target attributes and pipeline conditions apply (`T:7669–7682`, `:7722–7736`). The reference can share its **own** target's immutable weights; it must not share the candidate's mutable attention layer/cache objects.

The older `N/vllm__model_executor__models__qwen3_5_mtp.py` (`4b3ac08b...`) omits `quant_config` on its head constructor. `R/model.py:376–395` adds it; `T/model.py` adds a required `ModelOptNvFp4LinearMethod` check. **This omission does not show that the deployed MTP head was unquantized**, because native `load_model` replaces it with the target head. It does show that a standalone class loader must reproduce sharing or explicitly bind the same correctly loaded head. The checkpoint's mixed-precision map names an NVFP4 `lm_head` and excludes `mtp*` / `mtp.layers.0*` (`config.json:1969–1976`). Preserve the exact loader rules and record the actual FC/attention/MLP/head quant methods; neither “the whole MTP is NVFP4” nor the constructor's special `modelopt_fp4` FC comment describes this mixed checkpoint completely.

**KV is stateful and implicit in forward context.** Attention registers its layer name in `compilation_config.static_forward_context` and refuses duplicates; `self.kv_cache` is bound later (`N/...attention.py:368–384`). `get_attention_context` obtains the layer object from `forward_context.no_compile_layers`, its persistent `kv_cache`, per-layer metadata and per-layer slot mapping (`:667–707`). There is no explicit cache argument to `Qwen3_5MTP.forward` that makes an otherwise stateless call correct. Runner allocation/reshape/bind is at `N/...gpu_model_runner.py:6660–6715`; draft metadata initialization is at `T/eagle.py:7853–7936`, with the single-cache-group requirement. Reuse the backend cache specification and metadata builder, not a guessed KV tensor layout.

The smallest safe integration is therefore a native reference worker which loads the existing target/MTP sharing pair, allocates and binds **its own** MTP attention layer/cache once, and uses native first-pass/metadata/context helpers. It can remain sequentially scheduled relative to the candidate. Retrofitting MTP into the spec-off worker requires doing the MTP model registration **before** cache planning/allocation; calling `model.forward` after a spec-off engine boot without this work cannot create missing draft cache state. If the parent instead chooses a standalone MTP worker, it must supply the same vLLM/distributed configuration, loader and shared-weight semantics plus independent cache planning. Neither option needs a new MTP arithmetic implementation.

Bind cache history by logical position, request, generation and source event. Candidate first-pass MTP KV is written **before** its accepted-path remap (`T/eagle.py:822–1009`); proposal completion comes later. Capture pre-remap values after the model write and use the genuine proposal-end seal for O1, as already specified by the accepted design. Candidate publication correctness is checked against its own source bytes. The numerical reference must construct its logical history independently, not hydrate candidate-produced MTP KV and describe the result as an independent continuation oracle.

## Smallest connected test and remaining unknowns

The following is preparation for parent implementation; it authorizes no execution and does not replace the existing Q1 case manifest.

1. **First CPU wiring test:** call the actual source-bound first-pass helper through a minimal typed owner/stub (or extract that exact unchanged method with source hash recorded). Use distinct tokens, positions and hidden rows, a request tail, and one non-linear accepted-leaf index already in the authority fixtures. Verify the complete ID/position/hidden mapping and tensor-return convention. Exercise wrong leaf, stale request/generation, position-axis mismatch and alias-to-candidate-cache refusals structurally. This is a wiring test, not numerical evidence. No need to rerun accepted recurrence tests.
2. **First future connected model test:** use one already-declared nonempty prefix and one accepted off-spine path, with reference-owned MTP history. Run first-pass preparation plus **one subsequent MTP step** without reset, and repeat from the same independently owned initial state. This is the minimum connection that can expose a wrong first-pass shift, wrong return-hidden interpretation or lost KV history. Bind the same-input native/candidate comparison separately from the later comparison using independently computed target hidden histories. Save actual post-shift IDs, all position axes, source hidden rows, metadata/slot maps, cache before/after and full logits; checking only the final argmax would not validate state ownership.
3. **Preserve the categorical next-draft gate.** Current Hydra proposal selection uses full-vocabulary logits, spine `argmax`, and ordered width-3 candidates (`T/eagle.py:3158–3168`, `:4720–4805`, `:5280–5330`). Its fused selector is intended to match the native `argmax` **and** `torch.topk` results; `topk[...,0]` must not be silently substituted for `argmax` at exact ties. Freeze the executable native tie/rank behavior before evaluation, compare exact spine ID and ordered candidate IDs, retain set/rank disagreement and margins, and allow no `allclose` or margin-based exemption. A stable repeated native reference is required; an unstable tie case is unresolved, not dropped. One two-step smoke test only establishes adapter connectivity; it cannot pass the full declared next-draft corpus or replace all proposal-stage observations with root-only agreement.

Keep the approved deployed candidate settings and receipt bindings, including the mixed NVFP4 checkpoint/loader, full-vocabulary head, patched FA2 binary, BF16 attention KV, FP32 target GDN cache, block size 1024, APC/cache policy, graph configuration, sampler/seed and fixed32/Hydra route. Reference causal attention and candidate tree attention can use the same pinned FA2 binary without having identical dispatch/reduction shape. An eager diagnostic reference call is not permission to disable candidate graphs or reduce its deployed draft topology. The source-only FA2 installation receipt pins binary `28570f835ea72c99d03aab9fb03c494388bbb9c264ee4dc96eec047f50d7f857`; actual loaded dispatch and precision still require the eventual runtime receipt.

**Concrete remaining implementation gaps:** registration/allocation of the independent MTP cache; saved native-owned prefix history; source-bound event/input selection and current M-RoPE/MM/aux-hidden mode receipts; complete next-draft categorical/tie policy and observation coverage; the actual connected run. Existing pure-Python model/proposer seams cover construction, shifting, metadata and calls. There is no evidence here of a missing one-layer MTP implementation, nor evidence that these still-missing connections have already been qualified. No broader experiment or baseline expansion is needed to implement this bounded adapter.
