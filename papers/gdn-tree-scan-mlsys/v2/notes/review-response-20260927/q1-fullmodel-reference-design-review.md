# Q1 full-model reference and boundary-hook design review

27 September 2026. **Recommendation for implementation, not launch approval or an experimental result.** Scope: `PROTOCOL-Q1.md` U5/U8/U9 against the current local patcher/kernel, pinned native sources and `parent-default-precision-audit.json`. No GPU, model, server, task evaluation or remote operation was run. Only this note was written.

## Recommended split

Use a **separate, sequentially run spec-off engine as the primary target-model reference**, with a pinned native recurrence policy and the same checkpoint/loader/FA2 binary. Use independent persistent scratch state in the candidate process only for the **same-operand publication/component checks**. Add a **native MTP reference adapter** for the drafter surfaces: a spec-off target engine alone cannot qualify the complete continuation contract.

Keep three questions separate:

1. Did the candidate publish the selected path's own tensors to the correct destinations? Check exact copies, ownership, maps and fixed16 staging.
2. Does its GDN computation agree with native/float64 computation from the same recorded layer operands? Use the component references and their reviewed numerical policy.
3. Starting with the same complete O0 state and forced token history, how do independently executed full models differ at O1 and in the actual next target forward? Record cumulative state, hidden and logit differences; do not apply a component tolerance as an already-qualified full-model tolerance.

Replaying candidate-produced rings alone answers neither the third question nor whether earlier layers supplied the right operands. Conversely, naturally different full-model intermediate operands cannot share one candidate-conditioned C2 denominator and be described as a same-input recurrence comparison.

## Executable target-reference sequence (U5)

Implement a worker-side teacher-forcing harness around the actual runner, rather than repeatedly calling a chat API with growing prompts. Repeated prompt calls can recompute prefill and miss the continuation/cache behavior being tested.

1. Freeze token IDs for prefix `P`, root `r`, every physical draft row, accepted ancestor rows `p[0:L]`, and correction/bonus `z`, including absolute position tensors. `P` excludes `r`: O0 caches represent `P`; target verification materializes `r` plus accepted drafts; `z` remains pending. Use explicit token IDs so chat-template/parser differences cannot silently change this numerical experiment. Bind tokenizer and model manifests anyway.
2. Candidate: prefill the frozen prefix, prepare the real fixed32 metadata and capture O0 just before its forward. Run the real tree forward, force only the publication decision as described below, let all commits and the genuine drafter proposal finish, capture O1, then let the next real target forward consume `z` at position `|P|+1+L` and capture O2. Keep F2 continuation cycles continuous, with no resetting between cycles.
3. Stop that engine after its diagnostic corpus is saved. Start the reference from the same immutable image/model lock and explicit compatible loader/cache patches; do not reuse the historical FP8-default no-spec wrapper unchanged. No concurrent model residency is required.
4. Bootstrap the reference request with the same prefix and corresponding scheduler position. For the principal continuation-isolation comparison, **hydrate the saved logical O0 target states into the reference's own allocated cache rows/pages with in-place copies**, after allocation/metadata preparation but before consumption of `r`. Build destination maps independently from the reference block table and GDN metadata. Require positive native state indices (row zero is the null block), matching layer semantics/layout/dtypes and exact copied bytes. Keep a separate natural-prefill O0 comparison; it measures prefill differences and must not be conflated with a shared-O0 continuation test.
5. Execute one native target step for `r`, then each accepted draft token in ancestor order, each at its real absolute position. Force subsequent input tokens at the runner sampling/teacher-forcing boundary while preserving normal scheduler bookkeeping. After the last accepted draft, snapshot reference O1 before consuming `z`; then execute `z` and capture the full logits generated from its resulting hidden row. Do not substitute the previous step's correction-token sampling logits for these next-forward logits.
6. Compare the candidate's O2 **root row** against that single native `z` forward. To compare other active O2 rows, replay each row's root-to-node ancestor sequence from an independent scratch copy of the reference O1 state (including `z`), or a separately retained branch checkpoint. One linear chain is not an oracle for every sibling. The four inactive physical rows have no semantic next-token reference: retain their structural/visibility checks, without counting their arbitrary logits as valid branch outputs.

Freeze the spec-off configuration explicitly: current NVFP4 target and loader shim, BF16 full-attention KV and FP32 GDN cache as attested, block size 1024, compatible prefill/APC policy, seed/sampling transforms and tokenizer/position policy. Record module flags, generated patched source, FA2 version/dispatch and startup receipts. Same-shape native repeats precede candidate evaluation. Query shape, causal/tree masking, graph descriptors, GEMM tiling, speculative scratch capacity, physical allocation and reduction topology remain different; these are measured numerical differences, not automatically publication bugs.

### Why not a second full forward inside the live candidate engine?

An in-process reference can share weight tensors, O0 values and the same loaded native operators with less memory. But it must own independent persistent GDN/conv/KV buffers, metadata and forward context, and must invoke the native non-tree route without mutating global fixed32/sampler modes or compiled graph state. The current implementation has process-wide preseed routes, current/pending events, MTP proposal state and async gates. Temporarily rebinding `layer.kv_cache`, changing those globals or setting spec metadata to `None` in the live engine is not a bounded reference implementation.

A future explicit reference adapter can share immutable weights while owning all mutable state, but that adapter needs its own source/dispatch proof. For this stage, separate processes make that independence practical. In-process scratch replay remains appropriate for fixed16 native, token-by-token native and C2 comparisons on recorded rings; it must never register scratch banks as the candidate's preseeded banks.

## Boundary hooks and storage rules (U8)

Use a **small explicit diagnostic patcher extension** that imports a versioned `q1_boundary_hooks.py`, with unique anchor-count checks and generated-file hashes. The ASGI `Fixed32EngineIngressMiddleware` (`inference_proxy.py:2137`) is a request authorization guard, not a GPU-boundary observer. It may bind diagnostic request IDs, but cannot itself implement O0/O1/O2. A generic `sitecustomize` monkeypatch has weaker ordering/source guarantees than the existing patcher anchors.

| Hook | Concrete location | Required capture |
| --- | --- | --- |
| O0 | Runner after input, position, slot and attention metadata preparation, immediately before `_model_forward`; for a pure FULL step, cross-bind the wrapper's pre-`entry.cudagraph.replay()` anchor at patcher `:41972–42055` | Cache contents plus exact prepared input IDs, all position axes, prefix lengths, per-layer running indices, block/slot tables, physical permutation, masks, owner/generation/request key, graph ID/signature and stream identity |
| O1 | Immediately after the genuine proposal-end seal succeeds, **before** the async sample-gate release allows execute(t+1) | Published target and MTP logical state, selected hidden-row handoff, emitted/pending token contract, consumed payload/slot-restore receipt and new census event; assert pending event/proposal/payload cleared and seal count advanced once |
| O2-target | Runner immediately after the actual `compute_logits(sample_hidden_states)` for forward(t+1), before grammar/sampling processors or mutable output reuse | Full raw logits, `logits_indices` and inverse logical row map, hidden rows, actual input IDs/positions, consumed O1 generation and post-forward target state |
| O2-draft | The subsequent real proposer input and top-k/publish boundary, associated with the same forward/event | Actual target hidden-row selection, next-token/position inputs, full draft-head scores or sufficient margin evidence, categorical top-k IDs/ranks and actual MTP KV map |

O2-target and O2-draft are separate phases: a drafter result after sampling(t+1) also depends on that cycle's selected path/pending token. Label both event IDs and force the same decision before comparing them. Do not attach step-t proposal top-k to step-(t+1) target logits as if they were produced together.

Allocate shadow buffers once outside capture. Snapshot with `shadow.copy_(live)` and, only where a diagnostic reset is part of the design, restore with `live.copy_(shadow)` into identical storage. Preserve tensor objects, `data_ptr`, strides, offsets, bank tuple identity, bound path/ring/spec buffers and captured graph objects. Snapshot/restore all mutable surfaces used by that diagnostic, not merely recurrent rows: conv history, target/MTP KV, draft/input/position buffers, metadata, and relevant ownership/control state. Prefer avoiding restoration of live runner Python state entirely by using a fresh request/process or independent reference state.

Copies must be ordered on the consuming stream, or use explicit producer/consumer events for side streams. The CPU seal proves enqueue/lifecycle completion, not device completion. Record an event after snapshot copies and wait outside capture before host serialization. No `.cpu()`, `.item()`, disk I/O, allocation, synchronization or Python-only observer is allowed inside graph capture. A hook inside a captured model body runs on capture rather than every replay; per-layer diagnostics therefore require preallocated GPU copy nodes inserted before capture and a declared instrumented graph, not an ordinary Python forward hook. Start with existing rings plus outside-graph final hidden/logit hooks; add per-layer graph copy nodes only when needed for first-divergence localization. Such runs are correctness diagnostics, never timing evidence.

Guard O1 capture/serialization with the existing execute/sample ownership protocol. Do not clear the pending event, set completion booleans, release the condition or rewind counters to manufacture a boundary. Preserve the small pre-seal payload metadata in the hook receipt before the real code clears it; require the real seal to succeed before labeling O1 complete.

## Forced common acceptance (U9)

Place the diagnostic handoff after `fr13_fixed32_cfwd_logit_direct_commit` returns its five cache-owned products and before `_fr13_fixed32_device_commit_route` consumes them (`fr10_phase4_patch_vllm_tree_gdn.py:20610–20630`). Run the real TAW and its work callback, save its natural products to shadow storage, then `copy_` a prevalidated forced tuple into those **same five tensors** on the same stream. This tests publication/continuation conditional on a chosen decision; it does not test sampling correctness or acceptance frequency.

For B1 with accepted depth L, construct independently from the topology authority and observed draft IDs:

- output tokens `[draft[p0], …, draft[p(L−1)], z, -1, …]`, shape `(1,32)`;
- output length `L+1`, shape `(1,)`;
- root-inclusive physical accepted rows `[p0, …, p(L−1), 0, …]`, shape `(1,16)`;
- accepted length `L`, shape `(1,)`;
- last accepted physical row `p(L−1)` or `0` for root-only, shape `(1,)`.

All five are int64 on the original device; the route performs its normal int32 publication. The current root is implicitly committed and is not emitted a second time; the pending correction/bonus is emitted but not yet materialized. Validate the exact root-relative row convention, active-mask membership, parent chain, token-position consistency and padding before the handoff. The route's geometry/ownership guards remain active, but are not an independent ancestry oracle. Preserve natural versus forced product hashes separately, include case/step/request/generation binding and consume each decision once. For negative cases, corrupt one declared surface and require the appropriate independent structural detector/guard to reject it; do not silently repair the injected value.

If future staging captures TAW and commit in one graph, this host seam is not available: the forced copy must become a declared pre-captured operation reading a fixed-address diagnostic decision buffer, refreshed before replay. Do not claim a Python callback ran between two nodes of a replayed graph. The current protocol/boot must attest which sampling route executed.

## MTP and final decision boundaries

A spec-off engine has no proposer, no MTP cache and no draft top-k. Qualify MTP in two bounded layers:

1. **Publication mapping:** capture the actual pre-remap MTP source values after they are written and before KV1 remap; independently derive accepted destinations from the authority and flat logical map, compare the real remapped bytes, verify slot restoration, untouched regions, payload consumption and seal. This checks selection/copy correctness using candidate-owned values.
2. **Numerical continuation:** a separate native `Qwen3_5MTP` adapter with its own persistent KV history consumes the reference target hidden states and the exact token/position shift passed to the real proposer. Pinned `qwen3_5_mtp.py:121` combines token embeddings with target hidden states before its attention layer. The runner passes `target_token_ids`, `target_positions`, `target_hidden_states`, `next_token_ids` and selection indices (`gpu_model_runner.py:4660–4732`); the loaded proposer supplies further alignment. Bind the current generated `eagle.py`/base proposer source before implementing that shift—do not guess it from target positions or reuse candidate gather output as the oracle. First run a same-input MTP adapter check; then compare independent target-hidden histories and report the resulting top-k differences as cumulative numerics.

For a fair next-cycle target comparison, keep tree topology, physical draft IDs and forced decisions identical even if each arm's naturally produced MTP top-k differs. Save natural proposals before any diagnostic forcing. Otherwise later target-input changes confound state-consumption differences.

Before implementation review, produce a small source-bound design manifest with: token/position fixtures and denominator; O0 logical schema and independently constructed maps; explicit native packed/non-packed policy; candidate and reference patch diffs; actual generated FA2/GDN/runner/proposer/conv source hashes; pointer-invariance assertions; ordered O0/O1/O2 receipts; and the missing native-only full-model calibration plan. Retain actual logits/margins, TV/KL and categorical top-k disagreement without inventing a tolerance. Do not turn current Q1.2a component characterization into full-model qualification.

## Addendum: native-first order and honest logit-policy scope

**Operational ordering correction:** the numbered candidate-first trace above explains paired data flow, but must not be the execution order for choosing a numerical policy. Prefer **native-first calibration and a native-owned logical O0**, followed by policy review/freeze, then candidate execution. Candidate input-only capture is a fallback, not necessary for the first bounded experiment.

1. Freeze disjoint calibration/evaluation prefixes and explicit root/draft/pending token fixtures before either arm's comparison outputs are inspected. Use source-bound archived token inputs or predetermined valid-token fixtures; do not require fresh candidate proposal results to define the calibration corpus. This qualifies forced continuation, not proposal quality.
2. Run only the operator-aligned nonpacked native target and the separately labeled native-default control on the calibration split. Prefill `P`, allocate native caches and save a logical O0 before consuming `r`; retain all logical target KV history, GDN state and conv history with dtype/layout/position metadata. Repeat native continuation from that O0, including the actual pending-token forward, in the planned repeated/fresh-process controls. Prepare native MTP calibration separately where its source-bound adapter exists; otherwise leave MTP numerics explicitly unqualified.
3. Review and hash the native-only observations and the exact policy scope before a candidate boot/evaluation. Generate held-out native O0 snapshots under the frozen procedure; held-out continuation outputs must not tune policy. Each comparison pair must cite the exact O0 snapshot digest it shares.
4. Only then boot/preseed the candidate, bootstrap the matching request/prefix for legitimate scheduler ownership and allocation, and hydrate the **native logical O0 into existing candidate storage** at the last pre-forward boundary. The pinned runner performs `preprocess_mamba`, slot construction and metadata preparation before `_model_forward` (`gpu_model_runner.py:3930–4027`); import after those operations, before graph pregather/forward can consume state. Map native logical history to candidate running rows/flat prefix KV using independently constructed destination maps; convert layout only with a byte-preserving permutation. Import only corresponding conv history, not speculative scratch as if it were native state. Candidate-only scratch and graph buffers remain allocated and initialized by the candidate; do not copy native physical IDs, owner counters or metadata over them.
5. Verify exact logical O0 round-trip bytes, unchanged candidate pointer/stride/tuple identities and valid owner/position metadata, then execute the existing O0/O1/O2 design. This is feasible in principle because `_fr13_fixed32_committer_fast_state` binds storage identity, not an immutable initial content value. The importer and its negative tests still require implementation review. Hydration establishes a continuation-isolation case; it does not qualify natural prefill/APC bootstrap. Those remain separate cases. A spec-off O0 contains no MTP state: use a separately bound native MTP O0, or limit this first case to target continuation and independently checked candidate MTP publication.

**What native-only full-model calibration can freeze:** repeat determinism/noise, finite-value requirements, normalization and comparison metrics, precision strata, categorical top-k/rank definitions, native-default versus operator-aligned differences, and a threshold for the narrow claim “within native repeat variability.” A deterministic native baseline supplies a zero observed repeat envelope; it does not justify an arbitrary nonzero candidate logit tolerance. Nor does the packed/native gap automatically become an allowance for the tree route. Known state perturbations can diagnose sensitivity and power negative controls, but cannot manufacture a valid acceptance budget.

There is currently no independent float64 **full-model** logit truth or justified transfer from component errors to a global logit bound. Therefore freeze initial cross-route logits/TV/KL/margins/top-k as **raw diagnostics with no numerical pass/fail qualification**, alongside exact structural checks and any separately approved component criteria. Call this a frozen diagnostic measurement policy, not a completed full-model numerical acceptance policy. Candidate diagnostics may proceed only under that explicit scope; they cannot close Q1 or authorize downstream stages that require full-model qualification. A substantive logit acceptance rule needs an independently justified reference/error criterion reviewed before a new held-out evaluation. Never widen it after inspecting candidate errors.

If candidate-produced O0 later becomes indispensable, its alternate route is capture-only before freeze: stop at pre-forward, expose only declared input/state snapshots, and do not execute/save downstream candidate comparison outputs. Record unavoidable boot/profile work separately. This is more complex than native-owned O0 and offers no advantage for the first target-only continuation experiment.

## Addendum: a supported operational decision gate

**Yes: adopt exact next-forward greedy-token agreement as a predeclared, narrower full-model gate.** This is scientifically meaningful when conjoined with the exact structural checks and separately qualified recurrence/state comparisons. It requires no invented global logit tolerance or float64 full-model truth: the estimand is agreement with a specified executable native decision on the finite tested set. This narrows the previous addendum's diagnostic-only recommendation for logits; it does not retroactively qualify an experiment or remove the separate MTP requirements.

Freeze before candidate outcomes: the operator-aligned nonpacked native reference, evaluation cases/cycles/observation rows, full vocabulary, score-processing policy, tie rule, repeat controls, and **zero allowed token disagreements**. The separately labeled native-default packed control is informative; it is not an alternative reference chosen case-by-case to rescue a disagreement. Every declared observation must be present, correctly associated and finite, with deterministic native decision repeats. A native repeat that changes the winner makes that case baseline-unqualified; it is not removed from the denominator or converted into permission for either candidate winner. Report any unqualified/missing case explicitly and do not declare the all-cases gate passed.

Prefer the **raw target-head argmax** for the first gate, with no grammar mask, penalty, logit bias or other score transformation. The pinned runner computes logits at `gpu_model_runner.py:4070`, then later applies grammar masking before sampling (`:4160`). Capture at the former boundary. Call the result raw greedy-token agreement. If claiming agreement with the engine's served greedy decision instead, freeze and reproduce all applicable score transforms and legal-token masks in both arms; temperature alone is not a complete sampling-policy specification. Preserve raw logits before any in-place processor mutates them.

**Pending-token semantics:** O1 has materialized `P + r + accepted_drafts`, while `z` is pending. Both arms must actually consume the same `z` at position `|P|+1+L`. Compare argmax of the resulting O2 root logits, which predicts the token **after z**. Do not compare z itself, the step-t logits used to select z, a sibling row, or a pre-remap stale result. For F2, enforce this at every declared cycle without state reset. Additional branch decisions need their independently executed ancestor histories; inactive padding is excluded by the frozen scenario definition, never by observed disagreements.

Use an explicit deterministic tie rule, such as smallest token ID among exactly maximal stored scores, and verify it matches the intended native decision routine if calling it an engine decision. A stable exact tie can pass exact token agreement under that rule, but must be counted as a tie with no positive-margin robustness certificate. Small-margin disagreements remain failures of this strict operational gate; margin bins explain sensitivity, not exemptions. Freeze bins or publish continuous margins, and retain all disagreements.

For an optional sufficient certificate, let `n` and `c` be the finite native/candidate score vectors, center each by its own mean using a frozen analysis precision, and set `E = max_i |(c_i−mean(c))−(n_i−mean(n))|`. Let `m = n_top1−n_top2`. **`2E < m` certifies the same unique argmax** for the recorded vectors. Centering removes irrelevant scalar shifts without changing argmax. The converse is false: equal argmax can pass the operational test even when this conservative certificate fails; ties have `m=0` and cannot satisfy it. Keep direct token comparison mandatory, and report certificate coverage separately. Centered/log-softmax errors, TV/KL and drafter top-k differences remain diagnostics with explicitly defined precision/temperature and finite checks.

The permissible conclusion is: “Across the declared forced-path cases, the tested continuation preserved the specified native next-token greedy decisions, alongside the stated structural and state checks.” It does not establish equal distributions, stochastic sampling preservation, all future greedy decisions, free-running trajectory equivalence, or task quality. The parent can explicitly redefine the full-model decision portion of Q1 to this scope before launch; passing it cannot silently substitute for still-open state, MTP, lifecycle or coverage gates. A wrong-state negative remains a required structural/state detection even if its argmax happens to agree.
