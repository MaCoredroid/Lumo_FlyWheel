# Q1 full-model native-first implementation review — 2026-09-27

**Disposition: changes required before even a native calibration smoke.** The native-first design and chosen hook locations are useful, but the submitted implementation can omit or misidentify required state, collide across repeats, and report an invalid case as successful. This review authorizes no GPU/model launch and changes no gate. Only this note was written; no remote commands or GPU operations were performed.

Reviewed package: `FREEZE-Q1-FULLMODEL-DESIGN.json`, canonical `018c8a661f8b5d82aea0cfe7e8d1b63c344a9db08686aa4e185da56cfc79e4af`. All **18/18** frozen payload hashes match locally. All **6/6** prefix byte hashes match both the token fixture and prefix-plan manifest. The five implementation modules parse as Python. The delivered log reports 141 CPU tests, including 21 new package tests; these are not model runs or experimental observations. I did not rerun the tests. Paths below are relative to `v2/experiments/review-response-20260927/` except explicit repository `scripts/` paths.

## What is sound within the bounded design

- The fixtures are candidate-blind, deterministic token assignments derived from the six pinned prefixes and current topology. Their 168 chains split into 84 calibration and 84 held-out evaluation cases, with 28 paths per prefix and no inactive physical rows on accepted paths. They test forced target continuation only; they do not establish natural proposal quality or continuous multi-cycle behavior.
- The O0/O1 observation before `_model_forward` is after the pinned runner's mamba preprocessing and attention metadata preparation. Raw O2 immediately after `compute_logits` precedes grammar and sampling. Teacher forcing after `_sample`, before `_update_states_after_model_execute` and bookkeeping, is the appropriate host seam for this spec-off, single-request reference. These ordering facts are supported by the pinned runner around lines 3930–4071 and 4162–4173.
- O0 is after P and before root r; O1 is after root plus accepted drafts and before z; O2 is the logits produced by actually consuming z, predicting the following token. Root-only has distinct O0 and O1 observations.
- The nonpacked primary and separately named packed control preserve the intended distinction. Current native source supports skipping the packed branch through `enable_packed_recurrent_decode=False`; the primary uses the same native sigmoid-gating update family as accepted replay. That does not make whole-model dispatch, matrix tiling, graph behavior or prefilling identical.

## Required repairs

### 1. Retain patched FA2 in both reference arms

`tools/q1_spec_off_engine_config.py` explicitly removes the forked binary and requires “FLASH_ATTN (stock, unpatched)” in the boot receipt; the plan recommends accepting it. This conflicts with the user's explicit instruction that all variants use patched FA2. Treat that choice as resolved, not an open parent decision.

The minimal native reference may retain the ordinary one-token causal **FLASH_ATTN backend** while loading the **same pinned forked FA2 binary** and compatible Python interface used by the candidate. The backend name alone does not identify the binary or force FA2. Bind the installed `.so` SHA, interface/backend source hashes, actual selected FA version and executed native operator. Fail if it silently chooses stock FA2, FA3, or Triton. Do not fake a fixed32 tree query to obtain binary parity: ordinary one-token and fixed32 tree dispatch remain declared geometrical differences within the pinned implementation.

Existing source provides the install pattern in `scripts/fr14_leg3_launch_nomiddleware.sh:6701,7331–7332` and `_patch_flash_attn_interface` in `scripts/fr13_patch_fa2_tree_bias.py:4644`. The latter explicitly dispatches `varlen_fwd_tree_bias` only when tree bias is present and otherwise calls `varlen_fwd`, so a non-tree reference path through the fork is supported by the source design. Reuse the minimal compatible installation/interface edits; do not import every tree/committer modification into the native engine. Review the resulting hashes and actual FA2 version selection before smoke.

### 2. Fix attention-KV extraction before archiving or comparing O0

`q1_reference_hooks.py:228–240` treats `kvc.shape[0]` as the block count, loops over **all** request cache groups for **every** attention layer, and reads `kvc[b]`. This does not bind an attention layer to its actual cache group or backend tensor layout. The pinned TREE_ATTN shape is `[2,num_blocks,block_size,num_kv_heads,head_size]`; the runner explicitly preserves each backend's logical cache shape after its stride permutation (`gpu_model_runner.py:6564–6595`). Under that layout, the current loop skips block IDs >=2 and can hash the entire value-cache plane for block ID 1. The native FLASH_ATTN layout must be read and bound explicitly as well; a fake CPU test shaped `(4,2,8)` does not validate it.

Required replacement: derive the layer→cache-group/backend mapping from the runner configuration, identify that group's request block table and kernel block-size conversion, unbind/index the declared K/V axes, and serialize valid logical token positions in order. Record per-layer shape, dtype, strides, storage offset, group, physical block mapping, valid-token extent and canonical logical order. Reject missing, duplicate, out-of-range or truncated coverage. The current `max_kv_blocks_per_layer` slicing must not silently turn incomplete capture into a valid logical digest.

Full last-block bytes include unmaterialized suffix slots. Those bytes can contain stale allocator/request data and differ between repeats without any logical-state difference. The logical digest must cover only tokens materialized at O0/O1, with full-block and tail extents recorded; keep a separate physical-block diagnostic hash if useful. This is also necessary to avoid hydrating stale slots into the candidate.

### 3. Make snapshots reusable across repeats and restorable

Raw names at hook lines 221–222,239,303 contain case ID/tag but omit arm/process/repeat. With the driver's shared per-process output directory, the second repeat of a case raises `FileExistsError`. The error is swallowed into invalid state, and the driver can wait 30 minutes for an unsealed case. Include an immutable run/arm/process/repeat/case observation identity in references, or store payloads by content hash with exact-byte verification on reuse. Do not overwrite earlier observations.

For usable O0 restore, archive full logical recurrent/conv bytes and attention KV bytes with independent destination mapping instructions, not hashes alone. `save_kv_bytes=False` cannot support the planned later O0 import. A bounded storage design is appropriate: content-address complete logical KV blocks, store only valid last-block tails, and represent each O0/O1 through a manifest of shared prefix blocks plus its newly materialized tail. Preserve every case's mapping, extent and hashes even when bytes deduplicate. Verify a CPU logical reconstruct round trip before native smoke; the later GPU importer must `copy_` into preseeded destination storage, preserve pointers/strides/tuple identity, and byte-check its logical readback.

At the declared 16 attention layers, 4 KV heads, dimension 256 and BF16 K/V, the three calibration prefixes contain approximately 0.884, 1.897 and 3.938 GB of **logical KV payload** each. These are arithmetic sizes, not measured allocations. Rewriting whole-prefix KV for every path/repeat would multiply them needlessly. Shared full blocks plus valid tails retain evidence without blindly writing gigabytes hundreds of times; any O0 divergence gets its own content objects and stays visible.

### 4. Verify the actual consumed input and complete observation contract

The hook receives prepared `input_ids` but ignores it, reading `input_batch.token_ids_cpu[idx,ncomp]` instead (`:259`). The pinned runner's `_prepare_input_ids` can replace inputs from GPU `prev_sampled_token_ids` under async scheduling (`:1609–1702`), so the CPU buffer is not sufficient evidence of what the model consumed. Read the actual prepared token at the request's metadata-derived position after input preparation. Validate its absolute position against the fixture; current code merely records `positions` and never checks them. Bind the effective async-scheduling setting and ensure the chosen capture handles it rather than assuming synchronous behavior.

Require runtime prompt IDs and their expected hash, not the current optional check (`:166–167` skips parity if either is absent). Record and compare the exact chain token/position sequence, with one scheduled token per forced chain step, no missing/repeated step, exactly one O0/O1/O2, and actual z consumption before O2. Missing `input_ids`, unsupported positional rank/layout or unexpected scheduling must invalidate the observation explicitly.

At state capture, enforce all 48 GDN and 16 attention target layers; validate each layer's metadata-authoritative row and cache-group mapping rather than using the first GDN layer's row unchecked for every layer. Require the expected packed attribute on every GDN layer, source-bound shape/dtype/stride contracts and all required finite state/logit values. The current optional attribute check and unconstrained layer count can accept partial capture. All-layer pointer identities are recorded now, but stride/storage-offset information and per-layer row mappings are still missing.

### 5. Seal invalid cases promptly and make the driver consume verdicts

`on_logits` records `all_finite=False` but still sets `o2_done=True`; `_seal_case` computes valid solely from an empty error list. It does not require O0/O1, complete input trace, layer coverage, a finite full-vocabulary row, or the configured vocabulary size. Add explicit mandatory-observation validation before a valid seal. Preserve nonfinite/missing observations as invalid, never silently omit them from the denominator.

Several failure paths leave the case pending indefinitely; a later control change can replace an unbound failed case or a case with `o2_done` without sealing it. Seal a uniquely identified failure exactly once and record whether the associated request is still active. The driver must read and authenticate the sealed document and raw hashes, check its run/arm/process/repeat/case, and require `valid=true`. Currently any file at the expected path increments `sealed`, and exit success tests only file existence plus prompt-token count. An invalid seal can therefore produce a successful driver exit.

After HTTP timeout or unsealed terminal failure, do not change the control file and admit another request while the prior server request may still be active. Stop the bounded run unless the prior request is demonstrably finished/aborted; preserve its failure receipt. Validate positive repeat count, exact requested case IDs, fresh output namespace and fixture canonical hash before issuing requests. These are lifecycle/accounting fixes, not extra experiments.

### 6. Make the rendered native launch actually locate and require its hooks

The config mounts the repository at `/workspace` and runs the repo shim under `/workspace/scripts`, but invokes the campaign patcher as `/workspace/tools/q1_patch_reference_runner.py`; the actual file is under `papers/gdn-tree-scan-mlsys/v2/experiments/review-response-20260927/tools`. `PYTHONPATH=/workspace/src` also does not expose `q1_reference_hooks` to the patched installed runner. Render real mounted campaign paths and add the exact tools directory to PYTHONPATH (or install the reviewed module explicitly). The package also needs a concrete, hash-bound job JSON, matching host/container control paths and terminal-token binding; these are not created by the current rendered launch.

For this instrumented reference, an explicitly set `Q1_REF_HOOKS_JOB` pointing to a missing/unreadable job must be fatal. Current construction silently disables all hooks if the file is missing. Assert job/arm/run identity, expected packed flag, state/KV archival policy and fixture hash at boot. Retain the intentionally disabled no-op behavior only when no reference instrumentation was requested. The existing immutable image/model/shim and runner-source checks should stay.

## Resolved choices and minimally bounded next stage

**Patched FA2:** required for both native arms as above. **Cache:** retain explicit `--mamba-cache-mode align`; the provided source shows that it selects the running block from sequence length and Mamba block size. Record actual resolved mode, group specs, effective allocation/kernel block sizes, FP32 SSM/BF16 KV dtypes, APC/chunked-prefill settings and the row selected after preprocessing. Matching flags alone does not establish identical O0 across cold/warm prefix reuse. Different physical row IDs between engines are expected; exact logical O0 is required for the eventual paired comparison.

**Repeats:** R=2 per process is the minimum useful within-process repeated-decision check. The planned primary A/B fresh processes remain required for the later native calibration matrix; packed-default is a separate diagnostic control, never a per-case fallback winner. Record cold/APC-hit/tail-prefill state per request. Distinguish within-process repeats from fresh-process observations, and do not characterize two repeats as exhaustive determinism.

**Next proposed smoke, after these repairs and a new reviewed freeze:** only the aligned nonpacked primary engine; only `calibration-short_available__c0__root-only`; R=2 in one process. It should produce two requests, each consuming `[r,z]`, and two complete valid O0/O1/O2 records with repeat-unique manifests, full usable O0 state, exact actual token/position trace, finite full-vocabulary logits, and a recorded greedy tie/margin result. Compare repeat identities and decision outcome, retaining any O0/cache difference. This is an instrumentation/native-calibration **smoke**, not full-model qualification, not completion of the 84-case matrix, and not permission for candidate or held-out evaluation. Missing/invalid evidence stops that smoke; no automatic expansion. Parent may subsequently gate the already planned calibration matrix and second fresh process after reviewing smoke receipts. This note itself gives no launch approval.

**Candidate draft forcing, for the later candidate package:** prefer the in-process proposer-output seam immediately after genuine `self.propose_draft_token_ids(...)` returns and **before** request-row ownership export and `_copy_draft_token_ids_to_cpu` (`scripts/fr10_phase4_patch_vllm_tree_gdn.py:24451–24497`). Archive the natural proposal, then copy the fixed physical-row draft IDs into the existing tensor after validating request/generation, shape, dtype, device and topology mapping. This keeps GPU consumers and CPU/scheduler mirrors consistent. Mutating only scheduler `request.spec_token_ids` is insufficient because current async paths retain GPU draft tensors and request-keyed copies. The root token must also be forced at the actual preceding sampled-token seam before those copies/first target forward. R-ACCEPT remains after real TAW and before publication; retain its natural five outputs and replace their contents only, with active-path/pending-z validation. These candidate hooks remain a separate implementation review and must not execute before the native policy freeze.

The genuine deferred-MTP seal remains the O1 candidate boundary. Forcing proposal IDs after proposal computation does not itself validate MTP state under those tokens; the declared target-only cycle-0 scope and independent MTP qualification must remain explicit. The eventual reducer must use the already frozen exact operational greedy decision rule, separately report stable ties/native-unstable cases, and retain all missing/unqualified cases. Native-only results may freeze repeatability/coverage and diagnostics; they cannot justify a new nonzero candidate logit tolerance.
