## Launch-blocking corrections

1. **Put metric operands on one device before subtraction.** `q1_oracle.py:143–147` changes dtype but preserves device. `q1_native_baseline_runner.py:211–213`, 239 and 259 pass cloned CUDA state/output against CPU C2 tensors. This raises a device-mismatch error after native work has run. Move both metric operands explicitly to CPU float64 before arithmetic; these are diagnostic computations outside timing. A CPU-only unit test can check the metric helper's device contract; include a CUDA-input/CPU-reference smoke assertion in the bounded runner before the fixture loop when CUDA is available.

2. **Never turn invalid references into apparent zero error.** `q1_oracle.py:150–158` counts only candidate nonfinites, then replaces every nonfinite difference with zero. A NaN in the reference with a finite candidate yields zero reported error and candidate nonfinite count zero. Return per-head and total counts for candidate, reference and difference separately. Mark metrics invalid if any nonfinite is present; use JSON-safe null/error fields rather than a zero error in an invalid head. Add tests for candidate NaN, reference NaN, both infinities, and overflow in the difference. `head_dim` at line 137 is ignored: either honor it via `movedim` or remove it and assert the documented leading-head layout.

3. **Bind completeness to the frozen manifest, not agreement between two outputs.** `q1_2a_reduce.py:21–24` only checks equality of process fixture sets. Two empty sets or the same subset pass; duplicate IDs are silently collapsed by the dictionary construction. Require the exact nonempty calibration ID set from the reviewed fixture manifest, reject duplicate/missing/extra IDs and mismatched per-fixture hash/seed/stratum/T, and require all expected variants and eight repetitions in both processes. Require distinct process identities/tags and matching manifest, runner, oracle, native-source and image identities. `q1_native_baseline_runner.py:148–162` currently only warns for fewer than eight repeats and allows arbitrary blocks/limits; bounded production mode must reject these deviations or the reducer must classify the run explicitly ineligible. Keep debug output separate from eligible characterization.

4. **Make integrity failure executable.** `q1_native_baseline_runner.py:262–275` labels a fixture DONE and exits zero whenever all fixtures reached the loop end, even when shape/dtype properties, reference checks, determinism or nonfinite flags fail. `q1_2a_reduce.py:56–81` prints flags but returns zero even if native sources differ, required rows are not DONE, repeatability fails or nonfinites occur. Add a distinct `integrity_ok` / `characterization_complete` decision and nonzero exit for missing/invalid data or failed declared determinism. This is not a candidate numerical-tolerance verdict. Report finite primary/per-token/padded-shape disagreements as characterization findings, not automatically as an intrinsic kernel defect; if policy later requires shape parity, make that a separately named rule.

5. **Cover every repeated native result in both processes.** `q1_native_baseline_runner.py:202–210` retains the untouched-null-row flag from the last primary repeat only. Its per-token variant (`223–240`) omits output nonfinite counts and checks only the final state of repeat zero. Record null-row integrity and nonfinites for every repeat, every token and every variant, including intermediate states and outputs. Retain raw tensors for any differing/invalid repeat; deterministic repeats may share one raw representative plus hashes. In `q1_2a_reduce.py:34–41, 55, 63–67`, add cross-process per-token **output** hashes and padded16 output-prefix hashes; inspect both A and B nonfinites, null-row checks and primary-vs-other-shape relations. The current `all_bitwise` stratum aggregation even omits the already-calculated primary output cross-process flag. A uniform matrix of process × variant × repeat × surface is less error-prone than selected hand-written flags.

6. **Enforce the reviewed identity at launch.** The launcher (`run_q1_2a_native_baseline.sh:25–40`) checks only `approved:true`, then records current hashes without comparing them to the gate's reviewed hashes. Bind the scoped gate to image ID, runner, oracle, reducer, launcher and fixture-manifest hashes and to the exact block/repetition/variant scope; refuse drift. The runner records native source/signature and package-export equality (`65–97`, 150–159) but does not require the expected values. Check the loaded native module hash against `000ab899…`, the package export against the same function, expected geometry/dtypes and expected fixture-generator/oracle provenance before GPU work. The repository mount is already read-only and image launch is by immutable ID, which should be retained. Preserve failure exit/receipt records even under shell `set -e` (`46–48`), and reject an existing output run directory so a retry cannot overwrite evidence.

## Oracle and fixture assessment

- **C2 is correct for the specified raw-operand mathematical reference.** `q1_oracle.py:44–95` casts the recorded input values once, then uses float64 normalization, softplus, sigmoid, V-by-K state updates and `floor(h/3)` GQA mapping. C2r (`98–134`) is named separately and explicitly disclaims CPU/GPU bit equivalence. The tiny scalar check, zero-key decay, beta-zero and GQA tests are useful independent/structural tests; sequence-vs-step equality is only internal consistency.
- **The loaded native source supports the revised dtype semantics.** `identity/native_source/fla_ops__fused_sigmoid_gating.py:123–166` uses fp32 loaded values and beta, rsqrt normalization, fp32 carried state, bf16 output when q is bf16, and stores state in the bank's dtype. Its wrapper (`181–199`, 225–239) accepts the exact arguments used by `run_native`; row 1 is a valid running state and row 0 is reserved. The older Lumo SCAN_ALIGN comments about a bf16 beta/state round trip describe another native implementation and are not this image's reference.
- **The reset/pointer strategy is appropriate for this narrow stage.** The runner allocates its own two-row fp32 bank (`191`), restores contents in place before each primary/per-token/padded repetition (`199`, 221, 246), and clones results before subsequent mutation. No Lumo graph is preseeded or executed here. That satisfies native-only characterization; it gives no credential for Lumo's pointer-bound committer or conv lease.
- **T=12 is the actual longest materialized Hydra27 path.** The topology authority's longest choice contains eleven draft decisions; adding the root gives twelve updates. I independently executed the pure authority locally and confirmed length 11 for the maximum choice. Do not change this to eleven root-inclusive updates. However, all current synthetic fixtures have T=12, so the stage only characterizes that length, its successive one-token states, and its fixed16 padded call. It does not execute all 28 topological paths or prove short-after-long graph behavior.
- **State/head diversity is useful.** Warm C2 state is generally nonsymmetric, q differs from k, and the three value heads per key head carry different operands. Tests explicitly check these facts. Calling each fixture an operator parameter set rather than an actual model layer correctly bounds the evidence.
- **Record realized threshold values, not intended pre-rounding offsets.** `q1_fixtures.py:79–93` forms desired `a+dt_bias` offsets and then rounds a to bf16. Consequently the exact offsets declared at line 37 need not survive. The test at `test_q1_fixtures.py:69–71` only establishes values on both sides and approximate proximity. Store realized x values/ranges and assert below/equal/above-threshold coverage if all three are claimed. Do not infer a native branch-edge test from pre-rounding values.
- **A coarse grid is not a guaranteed bf16 rounding-boundary fixture.** `q1_fixtures.py:39, 85–87` uses multiples of 0.25. Normalization, nonlinear gates and later sums need not stay exact; neither “3 mantissa bits” nor an output tie is guaranteed. Relabel this as coarse-grid diagnostic coverage, or deliberately construct and test an actual rounding-boundary witness. This need not delay a honestly labeled native-only characterization, but it cannot close the matrix's promised rounding-boundary obligation.
- **dt_bias dtype remains an explicit scope limit.** Float32 storage with bf16-representable values fixes the mathematical values, but does not prove the production dtype or identical generated native specialization. The native kernel promotes the loaded bias to fp32, so these fixtures can characterize the declared synthetic dtype. Bind the actual model parameter dtype before claiming a production-specific precision policy. Conv, full-model logits, KV/drafter mapping, captured workload prefixes and graph/cache lifecycle are out of this launch's scope.
- **Host/in-container C2 equality is a provenance check with a declared handling rule.** The current runner records exact host/reference discrepancies but never acts on them (`179–185`). Different CPU libraries can produce tiny float64 differences. Freeze which stored reference is authoritative, record both library/runtime identities, and reject unexpected drift or handle a predeclared reference-only bound. Never silently select whichever reference produces a smaller native/candidate error.
