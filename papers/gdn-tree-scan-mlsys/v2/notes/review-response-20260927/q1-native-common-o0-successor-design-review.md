# Native continuation from common O0: next-step design review

**Recommendation: implement a separately versioned native continuation successor that hydrates one fixed native-owned O0 per case, then repeats the unchanged forced continuation and pending-z decision check. Fixed FlashInfer tactics are not an established prerequisite.** This fills a requirement already present in the approved qualification design; it does not repair the historical result in place or authorize a launch.

## What the existing result does and does not establish

The accepted raw review reports 336 valid aligned observations (84 cases × A/B × R2), exact within-process repeats, 14/84 cross-process greedy changes and different O0/O1/full-logit hashes in all 84 cases. The frozen reducer's `baseline_qualified = stable and same_o0` (`q1_native_corpus_v1.py:240–257`) gives **0/84**. Preserve that result and its full denominator, including the 70 stable greedy cases that still failed common O0. The original corpus's separate packed controls and 672-observation aggregate remain a distinct unfinished scope; packed results cannot replace aligned cases.

`CORPUS.json` explicitly describes its O0 policy as reporting natural-prefill variability and requiring candidate pairs to hydrate an explicit native O0. It explicitly does not claim same-O0 native repeats. Thus these A/B observations confound different initial logical state with continuation execution: they demonstrate failure of the original natural-prefill/common-O0 prerequisite, but cannot establish whether the same native continuation changes its winner when started from the **same bytes**.

The parent operational decision contract requires both “Exact common logical O0 with independent maps and pointer-stable copies” and deterministic native decision repeats. The reference-design sequence step 4 and its native-first addendum already require in-place hydration into the reference's own allocation and repeated continuation from a native-owned O0. The accepted candidate hydration shows the relevant target-state import principle is executable; it does not substitute for implementing native destination mapping.

## Smallest valid successor

1. **New manifest/version, unchanged population and criterion.** Retain all 84 calibration cases, all three prefix lengths, all 28 declared paths, cycle 0, two new independent aligned processes A/B and R2 in each (336 observations). Preserve the same prefix/root/accepted-path/pending-z tokens and positions, raw-head finite/full-vocabulary rule, smallest-ID exact-tie rule, and zero allowed native-repeat winner differences. State clearly that this prospective amendment follows the failed natural-prefill study. Do not rewrite the original corpus, replace its rows, or move stable cases into a smaller “qualified” denominator.
2. **Freeze O0 sources by an outcome-independent rule.** For example, bind the archived aligned A/r0 O0 for *every* case, with no exception based on the old winner, margin, or candidate result. Freeze the 84-entry source mapping, original run/job/observation/record seals, object hashes and exact lengths, prefix/fixture identity and O0 logical digest before successor outputs. The archived records are valid state inputs despite failing the aggregate repeat criterion. They are not new hydrated observations: all new A/B/R2 rows must execute and prove their own import. Selecting one shared source per prefix is also possible but is a different mapping that must be explicitly frozen; do not mix rules case by case.
3. **Bootstrap ownership, then import at the real O0 seam.** Use a legitimate request with the same prefix to allocate native state and prepare scheduler metadata. Preserve/label its natural bootstrap O0 separately if recorded. At `num_computed_tokens == |P|`, scheduled count 1, after native preprocessing/block/slot metadata preparation and immediately before consuming root `r`, hydrate the fixed source into current storage. Existing reference hooks `on_pre_forward` lines 478–511 locate this seam. No Python counters, physical block IDs, cache objects or graph objects are imported from the source process. The current request must independently prove the actual root ID, every position axis, prefix digest, owner and native allocation.
4. **Prove complete target O0 before executing.** Required values are all 48 GDN FP32 SSM states; all 48 native BF16 convolution windows (three live taps with source shape `[3,10240]`); and all materialized prefix K/V in all 16 target attention layers, exported in native logical 64-token order with the final partial tail. Require exact layer sets, dtype/shape/extent, positive native GDN state indices, request-derived per-layer groups and actual block table units, valid/disjoint destination write spans under native storage aliasing, and authenticated raw source objects before the first write. After **all** writes, reread every imported region and reconstruct the full native-order per-layer and aggregate O0 digest. Every A/B/R2 observation and later candidate pair must equal the same bound per-case source digest.
5. **Retain native storage and fail-stop invariants.** Build native destinations from `non_spec_state_indices_tensor` and the actual request's group block tables, not source physical IDs or candidate fixed32 running-row assumptions. Snapshot tensor/storage/shape/stride/offset/dtype/device and live registry bindings before and after; use ordered in-place copies outside graph capture. Preserve the accepted H4 principle of guards over the exact complement of all planned writes, including cross-family aliases, plus preauthentication, final all-layer readback and a latch before first mutation. Any partial-copy, identity or readback failure makes the process unusable; no continuation/retry from partly imported state. Native conv padding/geometry and native64 KV maps must be validated explicitly. Candidate H4's fixed32 SSI tuple checks and physical-page assumptions are not a drop-in native importer.
6. **Execute, do not jump to the answer.** From imported O0, consume the same `r`, each accepted draft token in ancestor order, and then pending `z` at `|P|+1+L`, without resetting between those steps. Capture O1 immediately before z and O2 raw root logits after actual z consumption, before grammar/penalty/sampling mutation. Retain complete consumed-token/position trace, all O1 target state/KV bytes, all 248,320 finite raw O2 scores, smallest-ID winner, exact tie count and margin. Importing a favorable O1 immediately before z would skip the continuation under test and is not this successor.
7. **Keep the gate conditional and conjunctive.** Reuse the exact 84-case repeat denominator and categorical/common-O0 rule. A missing case, failed import, invalid state/logit payload, or variable winner stays in the denominator and prevents the aggregate target-decision prerequisite. Preserve O1 and full-logit differences as diagnostics; equal winners alone do not prove state or distribution equality. Separate recurrence/state, exact publication/ownership, wrong-state negatives, MTP, continuous-cycle and lifecycle gates remain required for full Q1. A root-only control can test the importer but cannot qualify this corpus.

## Identity and controls that must survive the successor

Keep the immutable image, exact checkpoint/tokenizer/config identities, model loader/patch sources, effective precision/cache dtypes, patched FA2 binary and actual layer dispatch, aligned nonpacked native recurrence, seed/sampling/raw-score policy and declared graph/APC/prefill settings. Bind the native importer, hook seam, generated source, source-O0 manifest, new job/corpus and reducer to each run. The reference-design distinction still applies: matching FA2 family does not mean candidate tree and native causal calls use the same arithmetic reduction topology.

Minimum powered importer controls are wrong/missing/short source object, wrong layer or native state index, stale request/group/block table, row/page collision under aliases, changed registry/view, post-copy corruption, partial-copy failure and wrong pending-z/position. At least one wrong-state control must be detected structurally/state-wise even if its greedy winner is unchanged. Reuse existing authentication, native-order digest and complement-guard primitives where their actual native geometry is supported; review the new connected native mapper separately.

## Native geometry feasibility: unchanged H4 engine can be reused

A bounded read of the actual archived aligned-A/root-short/r0 record (SHA `6805fb135ae5cebd7d6790fe605ffa3d3983b4bb221fa1a4954097222e08af27`) confirms native conv `[3,10240]` BF16, bank stride `[2097152,10240,1]`; native SSM `[48,128,128]` FP32, bank stride `[1048576,16384,128,1]`; and 16 exact conv pointer classes of width 3. In the first class, layers 0/1/2 use native groups 0/1/2 and rows 53/54/55. The target attention group is 3, with logical cache shape `[2,10896,64,4,256]` and stride `[65536,131072,1024,256,1]`.

These fit the unchanged low-level H4 engine: `plan_gdn_layer` admits state-axis size at least three with the actual row-major live window; native size three makes the extra conv-padding guard empty, which `_contiguous_pieces` handles explicitly. `q1_candidate_kv_reblocking_v1.layout` admits physical page size 64 and the observed interleaved K/V strides (64 is an exact multiple of its 64-token export unit). The native alias census matches the existing `expect_alias=(16,3)` requirement.

The minimal new implementation is therefore a **native live-cache/group/registry adapter feeding unchanged H4 `plan_all`/`apply_all`**, plus hook/manifest integration and source-bound controls. Keep `expect_alias` enabled. Populate its group-role field from independently verified native group metadata, with the exact expected layer partition and selected rows. Validate native geometry rather than copying candidate fixed32 assumptions. Its identity callback must inspect the native runner's live registry and cache views; it must not use candidate FR13 preseed tuples or fabricate them. The generic all-layer authentication, write-span collision checks, global complement guards, final readback/digest and mutation latch need not be weakened. This is source/metadata feasibility, not a connected native import result.

## Why not fix FlashInfer tactics first?

The retained source diagnosis identifies per-boot FP8/FP4 autotuning as a plausible dispatch cause, but saved winning tactics and effective loaded tensor digests are absent. It does not establish that the two boots selected different tactics, that tactics caused the first divergence, or that a fixed tactic would fix it. Shared O0 is already a required experimental control and directly removes the observed initial-state difference; introducing tactic replay first would add another operational change before testing that control.

Retain available effective dispatch/tactic and loaded-parameter evidence in the successor if it can be captured without changing its settings, but do not substitute a receipt for same-O0 repeats. If the correctly imported common-O0 successor still has variable native winners, it remains baseline-unqualified. Then use a bounded first-divergence diagnostic (equal consumed inputs/state plus effective embedding/norm/projection operands, weights/scales and selected tactics) to decide whether a separately frozen tactic-replay successor is justified. Do not repeatedly rerun until a favorable boot pair occurs. Disabling autotuning, loading an incomplete cache, or choosing tactics after seeing favorable outputs is not an approved shortcut.

## Explicit scope limit for MTP and later cycles

The smallest successor is **target-only continuation isolation**, using the spec-off target reference. The archived target O0 contains no native MTP history. Combining target hydration with independently generated natural MTP history would not establish common complete O0 for the drafter. A combined test must additionally bind a compatible fixed native MTP O0, its cache/hidden/input/position/history boundary and allocation identity; otherwise MTP remains separately unqualified. The newly reviewed MTP adapter does not retroactively supply that missing archived state.

Likewise, a per-case cycle-0 reset cannot stand in for the later continuous-cycle/lifecycle domain. Each required continuous sequence can be hydrated at its declared initial O0 only, then must continue without inter-cycle state resets under its own prospective manifest.

No experiment, source modification, GPU/model/container operation or gate change was performed for this design review. The raw-result counts are taken from the accepted bound A/B audit, not recomputed from tensors here.
