## Concrete repairs

1. **Finish actual source/launch/fresh-process binding before eligibility (lines 254–291).** The current reducer reads job/CORPUS-BINDING/terminal/boot documents but does not validate immutable container image, bound model/loader/tokenizer identity, actual generated runner/hooks/patch source, engine configuration/argv, approved launch identity, or distinct A/B engine/container lifetimes. Four directories and A/B labels do not establish four fresh engines. Its FA2 check covers binary and selector but omits actual interface/backend/layer source equality and explicit absence of bad/missing layer attestations. Parent already identified and is implementing this part; this is not a new objection to an unfinished launch wrapper. Reuse accepted native-smoke launch/boot evidence shapes and require all relied-upon sidecars in the final receipt. Require exact terminal driver/cleanup status and owned cleanup evidence: the current `startswith("COMPLETED_driver_rc=0")` predicate accepts `COMPLETED_driver_rc=0_cleanup_rc=7` with `cleanup_state=stopped_and_removed`.

2. **Check recorded cache-group and logit-dtype identity (lines 121–163, 166–184).** `snapshot()` ignores `group`; a valid byte-identical snapshot remains accepted after removing a GDN group, labeling a GDN layer as attention group 3, or labeling an attention layer as group 0. Check the pinned native layer-to-group map (the accepted smoke has GDN layer-index modulo 4 as groups 0/1/2, attention group 3) and bind it to the declared runtime cache grouping. This complements the existing exact layer names/geometry and prevents inconsistent mapping evidence from passing. `logits()` also accepts omitted `logits_dtype` or `torch.float64`. Require the declared native source dtype (`torch.bfloat16` for this image) as well as the already-enforced FP32 serialized storage. These findings concern evidence integrity, not a change to raw-argmax arithmetic.

3. **Validate the fixture internally and the exact Cartesian population (lines 57–79).** The builder copies the claimed canonical digest without recomputing it and only checks three distinct prefix IDs and 28 distinct path IDs globally. It accepts an all-zero canonical digest. It also accepts replacing one case's `path_id` with another from the same prefix, leaving one prefix/path pair missing and another duplicated while retaining 84 unique case IDs and the global 3/28 counts. Recompute the canonical digest with the fixture generator's rule (exclude `generated_utc` and the digest field; use its exact canonical serializer), reject duplicate prefix IDs, and require exactly one member of each expected prefix × path pair. Check each case's ID/cycle/path/accepted length/chain/positions/z consistency against the frozen fixture semantics; do not infer that consistency from case counts. The gate should independently bind the intended fixture bytes, not allow an altered fixture simply because a newly built manifest hashes it.

4. **Recompute driver parity from recorded values (lines 286–287).** The reducer trusts `prompt_token_parity=True` and does not require `prompt_tokens_sent == usage.prompt_tokens == frozen prefix_len`. Nor does it cross-check driver `case_id`, `repeat`, successful sealing/problem list, or its aggregate verdict and expected 168 receipts. Add these direct consistency checks; require the exact expected driver receipt set and source-bound aggregate completion. This is a source finding, not a claimed full-pipeline false-pass reproduction. Case/control/trace validation already provides useful independent evidence, but it does not make a contradictory HTTP accounting receipt valid.

## Checks that are already appropriately strict

- The reducer rebuilds the corpus and job from fixed constants, requires four distinct run paths and distinct allowed arm/process pairs, and iterates every expected case and repeat. Case-seal file membership is exact, including refusal of unexpected INVALID-control JSON files. It requires all expected case/driver files in the terminal member index.
- `Objects.get()` authenticates bytes and length, rejects conflicting dtype/length reuse, and checks BF16/FP32 exponent bits for nonfinite values. State validation enforces all exact 48/16 layer names, conv/SSM geometry, positive state rows, kernel-block geometry 64 × 4 × 256, exact logical-block and valid-tail coverage, unique positive physical KV IDs and recomputed aggregate digests. Identical logical bytes under different valid physical mappings remain allowed.
- O2 is reduced from the complete raw 248,320-entry vector. Smallest-index max, exact ties, top2 and margin are recomputed; saved summary mismatches fail. The supplied stable-tie control passes and changing the claimed winner fails.
- Case/control identity and pending-chain/position/computed-count checks bind O0/O1/O2 to the expected boundary. Per-case A0/A1/B0/B1 membership, common O0 and stable winner are separate from full-logit and O1 byte equality. Different winners in different cases are allowed; changed same-case winner/O0, duplicates and missing repeats make that case unqualified. Packed results remain separate and cannot rescue the primary.

`main()` currently exits successfully even when the returned `primary_baseline_qualified` is false (lines 293–318). This is acceptable for a characterization writer only if its consumer explicitly checks the saved eligibility field and exact denominator. It must not be treated as a qualification pass merely because the reducer process returns zero. Missing-data exceptions also produce no summary: preserve the collection's incomplete denominator/failure receipt outside that exception rather than silently dropping the run.

The planned recovered-smoke CPU integration fixture is valuable and needs no new GPU work. Keep its explicit one-case A/R2 scope; do not relabel it as the complete A/B population. Add focused controls for the four repair groups above, particularly one source-complete positive run-binding fixture and an A/B identity alias negative. No numerical threshold, experiment population or model setting needs changing to close these findings.
