A tensor's values, strides, node identity and source generation all belong to that boundary. Equal raw arrays are insufficient to claim equal effective normalized operands.

TreeWY's normalization differs mathematically near zero. Normalizing Lumo's inputs first does not fix it: the author kernel renormalizes them unconditionally. An aligned TreeWY port must have an explicit, separately hashed source diff replacing the normalization in the invoked kernel with the agreed `+1e-6`/rsqrt policy, and must keep its reference consistent. If the mask-free chain wrapper is used, its separate normalization sites also need the same declared change. Preserve the original files byte-for-byte. Keep the dot mode explicit; changing epsilon does not remove the default BF16 contraction policy, and turning BF16 dots off does not establish bitwise recurrence equivalence.

For a normalization-aligned Weaver port, prepare unscaled normalized q/k in FP32 using the agreed native operator, use `norm=False`, and retain that same FP32 key in accepted replay; keep recorded v/a/b values and declared output dtype. Simply using `TreeVerifyStash(dtype=BF16)` for the normalized key introduces an extra BF16 rounding absent from native/Lumo's internal normalization. Conversely, changing the stash dtype globally without recording all affected tensors is not an adequate alignment declaration. A local FP32 normalization/stash adapter is a **local contract-aligned port**, even when the verifier and replay kernels remain byte-identical. Its required conversion/storage work must be timed. Author serving behavior can remain separately represented once its missing helpers are pinned.

Additional precision traps:

- Weaver K0 uses `_dot(...,"tf32x3",BF16_K0)` at line 137 regardless of the wrapper's `precision="ieee"`. Thus `ieee` is not an all-IEEE-arithmetic identity. `bf16_mode="all"` changes K0 further. Pin every mode rather than inheriting the environment; no need to add a sweep.
- Weaver's in-kernel optional normalization has epsilon parity but uses div/sqrt rather than native rsqrt. Pre-normalization rounded to BF16 creates another, larger seam. Report those separately from compact-solve error.
- All three wrappers apply query scale internally. Supply `scale=128**-0.5` explicitly with **unscaled q**. The archived E7a `Operands.q` from `lift()` is already scaled and must not be passed as raw q to these wrappers.
- State storage being FP32 does not establish FP32 arithmetic or recurrence equivalence. Ordinary and near-zero inputs must retain the approved separate accounting; a near-zero TreeWY author-default mismatch is not evidence of an inherent WY instability.

## 3. Complete recurrent-cycle endpoints

Freeze a finite sequence of M verification/forced-acceptance steps. Begin with the same materialized recurrent state and end with each method's selected state materialized in its durable bank. Share logical operands and accepted paths across arms; do not force equal output values or states after each cycle. Each method carries its own previous published state through the sequence. Selection may be forced for this component comparison, but then the result is **GDN verification plus accepted-state publication**, not a full-model serving cycle, sampler comparison or stochastic-distribution result. MTP, convolution, attention/KV, logits and pending-token processing remain outside this boundary unless explicitly included equivalently.

**TreeWY:** `tree_wy_tree_commit_capture_triton` (751) first commits the previous accepted leaf from `vt/kk/gc`, then verifies and overwrites the stash for the current tree. The durable state after its kth call is one acceptance behind. Initialize the first stash with the author's positive-gcum sentinel (or its documented zero initialization) and valid positive slots; provide the previous leaf on each later call. For M logical verifications the final selected state needs a final commit. No exported commit-only function exists in the pinned Triton file. The minimal unchanged-code flush is an extra fused call: charge the entire call, discard its extra verification output/stash, and label its unnecessary verification work as finite-session flush overhead. Do not silently omit it, count its output as a logical verification, or subtract an estimated cost. A commit-only extraction would be a separately hashed local adapter, not unchanged author code. Freeze which route is used before timing. The reference `TreeWYResult.reconstruct_state` is a useful correctness check, not the production flush implementation.

**Weaver:** the complete fused route is gating/normalization/stash writes → K0–K3 verify → accepted leaf/ancestor metadata → `advance_ssm_states_along_accept_paths`. Both the fused and chunk backend variants use this accepted replay. `LazyGDNVerifyState` only holds factors; `gdn_tree_fused.fold_accepted` is a helper, not the backend's served publication route. Replay consumes the normalized key/value/FP32 g/beta stashes and updates `[L,pool,Hv,V,K]` in place. Preserve the all-layer replay grid and charge optional prefix-track writes if enabled, rather than inventing an equal kernel-launch count across methods.

**Lumo:** use the current prepared fixed32 path plus ring/cut-state exports, accepted metadata/staging, and `launch_tree_gdn_replay_all_layers` (16280). Its fixed32 branch dispatches to the persistent native committer; the generic function's old “one launch” description does not describe that branch. `_fr13_fixed32_committer_graph_body` (14551) stages fixed16 inputs and invokes the native recurrent update per layer in the captured graph. Bind existing banks and buffers during preseed; hydrate/reset their contents in place. Do not replace pointer-bound banks, use the archived Cat10 replay call, or time only the path-scan kernel.

Reset state **and stashes, sentinel/leaf/path/generation metadata** outside each timed finite sequence. Use disposable state for warmup/capture. Do not reset between its logical steps, which would hide publication and repeated-continuation errors. Record finite total, explicit flush cost/boundary and the approved latency distributions; ordinary verify-only or asymptotic timings cannot replace the complete finite interval.
