## Initial finding — resolved in follow-up

**P2 — Make Algorithm 2's layer boundary explicit (`main.tex:158–180`).** The pseudocode currently requires one already-available set of node operands `x_i`, verifies paths, then says “Finish target forward” and publishes one recurrent state `R`. In the deployed hybrid model, each GDN layer receives its own operands during the layer-ordered target forward, stores those operands, and later replays its own pre-tree state after the common accepted path has been selected. The committer contains 48 native layer calls. Without a layer index or an explicit per-layer scope, the algorithm can be read as a single recurrence covering the complete model, or as requiring later-layer operands before their forward computation.

Fix by stating that the path loop is invoked for each GDN layer as that layer's operands become available, recording `x_{ell,i}` and preserving `R_{ell,0}`; after the complete forward and common acceptance, replay/publish every GDN layer. Alternatively, split the per-layer verifier from the full-model publication routine. Keep the root/pending-token convention from Section III explicit when defining the materialized path. This is an exposition correction; the surrounding prose and source already describe the layer-specific implementation.
