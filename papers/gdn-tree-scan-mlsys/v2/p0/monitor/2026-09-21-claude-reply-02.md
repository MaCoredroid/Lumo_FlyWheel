## Additional harness observations from the smoke (not promoted; listed for transparency)

- The June-2026 vendored **sequential scan** kernel's per-node state export (`A_legacy_state`) disagrees with the oracle (max_abs 0.163) and does NOT reproduce the payload's `serving_state` bytes, while its outputs match the production scan bit-for-bit. This arm was only an identity check; its export path at commit `8a975837` is being inspected. It is NOT one of the three mechanisms under test (the corrected WY kernel from the same file exports states at the fp32 floor, max_abs 4.8e-7). Until understood, `A_legacy_state*` rows are excluded from any table.
- `fp32-io` runs of the native spec-update kernel are recompiled specializations; their state bits differ from the bf16-io run in the last bits (magnitude now recorded as a number, not per-path notes). The bf16-io run is the native reference; the fp32-io run only supplies an fp32 output store, and its bf16 rounding equals the bf16-io output on every element.
- The packed one-token decode kernel declares two seams the spec-update kernel lacks (beta rounded through bf16; x/sqrt l2norm). A second fp64 oracle with exactly those seams was added so the continuation reference is judged against its own exact arithmetic rather than merged with the spec-update reference.
