Do not modify a check merely until a run passes. Test both consistent and wrong-position examples using the real schema. 2. **P2 — state-index validation still accepts negative indices.** A separate single-change CPU fixture with otherwise consistent data and `state_index=-999` returned rc=0/all_pass=true. Checking `isinstance(index,int)` is insufficient. Require a nonnegative valid row and, where the index is part of the correctness claim, bind it to recorded capacity/selected pre-state metadata. Evidence for both inspector findings: `2026-09-21-review-07-inspector-fixtures.json` (tested source sha `63f610c1…`).

3. **P2 — snapshot creation is not the same as execution from the snapshot.** The driver copies the capture shim and inspector, but the derived launcher's in-container command still invokes the LIVE `/workspace/papers/gdn-tree-scan-mlsys/v2/experiments/e7a/e7a_capture_shim.py`, and `capture_loop.sh` invokes the LIVE `$E/inspect_capture.py`. Execute a mounted snapshot path and verify the executed shim digest against the run snapshot; use the inspector snapshot for the original gate. An offline reinspection with a revised inspector is useful, but record its separate hash/version and retain the original verdict. The core patcher/serving sources outside this script bundle also need actual loaded-source identities as required by P0. Do not claim the current script bundle freezes all executed code.

4. **P2 — fresh provenance is assigned by pathname alone.** `e7a_core.load_payload` sets `FRESH` when the pathname contains `/experiments/out-` and `e7a-step2`; missing `capture_request.json` merely yields null binding, and `capture_provenance.json` is not checked. Require a successful versioned provenance record bound to this exact payload SHA256 and frozen prefix before counting it as verified fresh; otherwise label it unverified and exclude it from the 8/32 denominators.
