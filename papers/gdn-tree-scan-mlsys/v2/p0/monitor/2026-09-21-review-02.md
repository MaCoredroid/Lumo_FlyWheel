## Concrete fixes

1. **P1: padded factor layout is compared with the wrong axes.** `launch_factor_verify` allocates U as `(B,N_PAD,VH,DV)`. Device lines 399, 409, 417, 429, and 551 apply `U[0].permute(1,0,2)` or equivalent, producing `(VH,N_PAD,DV)`, whereas oracle.u is `(N,VH,DV)`. For the historical payload, `(48,16,128)` cannot compare with `(10,48,128)`; CPU shape reproduction raises. N_PAD32 control additionally compares different padded lengths. Keep a canonical factor layout, slice to actual nodes, and assert shapes in every comparison before running the ladder. Recheck all B4, truncation, padding, and reorder branches.
2. **P1: manifest builder attempts to hash configuration values as paths.** `manifest()` line 588 uses every mods_paths value in `Path(v)`, but main passes `_fixed32_mode`, booleans, block sizes, and warp counts back alongside source paths. `src_paths` was already filtered but is rejoined. This prevents final manifest persistence even after a long run. Separate source-file paths from flag values; write a startup manifest before launching and finalize compiled hashes afterward, preserving crash status.
3. **P1 for tiny-gate interpretation: false NaNs from off-path masking.** Core `decay_ratios` computes exp for all pairs then multiplies by visible mask. With two nodes, g=[-100,-100], cum=[-100,-200], fp32 expdiff contains exp(100)=inf at the invisible (0,1) pair; inf*0 becomes NaN and can contaminate dense solves/reconstruction. I reproduced it. Use selection masking (prefer masking exponent inputs before exp) and ensure irrelevant pairs are finite zeros. Keep deliberate literal-ratio underflow diagnostics separately labeled. Add finite-value checks before interpreting any method failure.
4. **P2: signed ULP mapping is wrong across zero.** Current fp32 mapping reports +0 versus -0 as 4,294,967,296 ULP and negative minimum subnormal versus zero as 4,294,967,295. BF16 signed zeros return 65,536. Same-sign neighboring values may still work, so historical nonzero metrics are not automatically all wrong. Use a monotonic ordered-integer mapping and document signed-zero policy; test positive/negative adjacent values, crossing zero, infinities/NaNs. Keep byte equality separate.
5. **P2: replay timing closure changes its own input state.** `prod_replay` initializes bank[0]=h0 once, calls launch once, then returns the same mutating closure to warmup/timing. Production `_tree_gdn_replay_kernel` reads col0 with prev_len=1 and publishes root/first accepted state back into col0. Repeated launches therefore process changing h0 while compact commit reads a fixed h0. Reset from an immutable snapshot outside the measured region or use separate immutable source and destination rows with recorded equivalent semantics. Validate repeat outputs; state reset cost must be treated consistently.
6. **P2: no-server telemetry can abort the runner.** `set -euo pipefail` plus `ps | grep -i ... | grep -v grep` returns 1 when no matching vLLM process exists, before Docker or during finalization. Treat an empty process inventory as valid. At 22:12:19 UTC my independent nvidia-smi query had no compute process and 0% utilization; earlier telemetry showed activity, so resource state is changing. Whole-device utilization during our own run cannot by itself identify unrelated work; collect timestamped compute-process inventory too.
