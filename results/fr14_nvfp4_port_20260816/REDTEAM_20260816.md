## New findings the recon missed (all real, none blocking)

1. **Chat template materially changed in 3.8**: new system-message merge + a
   `reasoning_effort` mechanism (default `'xhigh'`, values xhigh/medium/low). FR13 serving
   is insulated (launcher pins `docker/chat_templates/qwen3-openai-codex.jinja`), but the
   pinned template is a 3.6-era artifact — template↔model mismatch is now a live quality
   question for exact16. DECISION NEEDED before QC banking: keep pinned template
   (harness-comparable) vs adopt/port the 3.8 template (model-native, likely better solves).
2. **pre_tokenizer regex changed**: 3.6 `[^\r\n\p{L}\p{N}]?[\p{L}\p{M}]+` →
   3.8 `[^\r\n\p{L}\p{N}]?\p{L}+` (combining-marks handling). Alters segmentation only for
   text carrying U+03xx-style combining marks — negligible for SWE/code traffic, but it is
   a genuine behavioral delta, not serialization. Decoder flags also changed
   (add_prefix_space/trim_offsets/use_regex true — decode-side).
3. **+7 added_tokens** (ids 248070–248076: audio/TTS specials) inside the reserved
   248044→248320 padding range. No id reassignment.
4. **unsloth config is a transformers-5.14 re-serialization**: top-level
   `head_dim/num_attention_heads/num_key_value_heads` keys added (values match 3.6 arch
   exactly: 256/24/4), `vision_config.model_type` renamed `qwen3_5` → `qwen3_5_vision`,
   `torch_dtype` → `dtype`. Boot risk to watch: the pinned image's transformers must
   tolerate the 5.x-style config (the official FP8 arm keeps 4.57-style — one more reason
   it is the de-risk arm). Also: recon said unsloth transformers_version 5.16.0.dev0 for
   dbirks; unsloth's own is 5.14.1 — cosmetic, recorded for precision.
5. **merges.txt not yet on disk** for unsloth at check time — indeterminate
   (download in flight); re-verify at download completion. tokenizer_config.json diffs are
   the added audio/vision special-token declarations plus the new chat template.
